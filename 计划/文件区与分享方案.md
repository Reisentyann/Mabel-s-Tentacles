# 文件区 + 分享 + 字段扩展方案

> 需求来源：① 客户需要「用户文件区」保存隐私文件 + 「全局文件区」共享文件；② 用户文件区分享时链接过期时间默认 1 分钟内；③ 现有 file_metadata 字段太少，需要补「创造时间」等字段。

## 一、文件区设计（全局 vs 用户）

**逻辑分区**（用字段标记，不搬物理目录，改动最小）：

| 字段 | 取值 | 含义 |
|------|------|------|
| `scope` | `global` / `user` | 全局文件区 / 用户私有文件区 |
| `owner_id` | TEXT，可空 | `scope=user` 时，文件归属哪个用户（客户） |

- **全局文件区**：`scope='global'`，所有人可见/可下载，等价现在的 `data/` 行为。
- **用户文件区**：`scope='user'` + `owner_id=某用户`，只有该用户（和后台管理员）能看/下。

**物理存储**：暂仍统一放 `data/`，靠 `scope`+`owner_id` 做访问控制；若后续隐私要求更高，再改成目录隔离 `data/global/`、`data/users/<id>/`（成本低，方案里留口子）。

**「用户」怎么识别**：沿用 MCP 的 `user_id`（QQ 号/客户标识，TEXT 宽松）。`write_file`/`describe_file` 增加可选 `user_id` 和 `scope` 参数，LLM 决定写全局还是写某客户私有区。

## 二、分享 + 过期时间

**新增 `shares` 表**（独立于 file_metadata，一个文件可多次分享、可单独过期/吊销）：

```sql
CREATE TABLE shares (
    key          TEXT PRIMARY KEY,        -- 随机短码
    file_path    TEXT NOT NULL,           -- 相对 data 目录
    scope        TEXT NOT NULL DEFAULT 'global',
    owner_id     TEXT,                    -- 用户区文件记录归属，审计用
    expires_at   TIMESTAMPTZ NOT NULL,    -- 过期时间
    access_count BIGINT DEFAULT 0,        -- 访问次数
    created_at   TIMESTAMPTZ DEFAULT NOW(),
    is_active    BOOLEAN DEFAULT TRUE
);
```

**过期策略**：
- `scope='user'`（隐私文件）分享 → **默认过期 1 分钟**（可传更短）。
- `scope='global'` → 默认更长（如 24h 或永久），可配。

**入口**：
- MCP 新增 `share_file(file_path, expire_seconds?)` → 返回 `{download_url}`。
- HTTP `GET /api/files/share/{key}` → 校验过期后下载，`access_count+1`，`last_accessed_at` 更新。

## 三、字段扩展（file_metadata 完整版）

### 新增字段

| 字段 | 类型 | 用途 |
|------|------|------|
| `scope` | TEXT | 全局/用户文件区 |
| `owner_id` | TEXT | 用户区归属 |
| `title` | TEXT | 简短标题（区别于详细 description） |
| `extension` | TEXT | 扩展名（.txt/.png），展示/筛选 |
| `checksum` | TEXT | SHA-256 哈希，去重/完整性校验 |
| `download_count` | BIGINT | 下载次数 |
| `last_accessed_at` | TIMESTAMPTZ | 最后访问/下载时间 |
| `expires_at` | TIMESTAMPTZ | 文件自身过期时间（隐私文件自动失效） |

### 时间字段（完整生命周期）

| 字段 | 含义 |
|------|------|
| `created_at` | **创造时间**（首次写文件/建元数据）——已有 |
| `updated_at` | 最后修改——已有 |
| `last_accessed_at` | 最后访问/下载——新增 |
| `expires_at` | 文件自动过期——新增 |
| `deleted_at` | 软删除时间——已有 |

### 字段总览（含已有）

- **标识**：`id`、`file_path`
- **作用域**：`scope`、`owner_id`
- **描述**：`title`、`description`、`tags`
- **类型**：`file_type`、`mime_type`、`extension`、`size_bytes`
- **完整性**：`checksum`
- **审计**：`session_id`、`user_id`（创建者）
- **扩展**：`attributes`（JSONB，颜色等）
- **复制**：`copied_from`
- **使用统计**：`download_count`、`last_accessed_at`
- **生命周期**：`expires_at`、`is_deleted`、`deleted_at`、`created_at`、`updated_at`

## 四、访问控制

| 文件类型 | 谁能看/下 |
|---------|----------|
| 全局 `scope=global` | 所有人 |
| 用户 `scope=user` | 该 `owner_id` 本人 + 后台管理员 |
| 已过期 `expires_at < now` | 不可访问（除非后台） |

- 下载/列表/搜索/详情接口都按 `scope`+`owner_id` 过滤。
- 当前 `api.require_auth=false`（开发期）时，访问控制退化为「靠调用方传 `owner_id`」；上线开鉴权后由 JWT 里的 user_id 做归属校验。

## 五、实施顺序

1. `file_metadata` 加字段（scope/owner_id/title/extension/checksum/download_count/last_accessed_at/expires_at）+ 迁移
2. `shares` 表 + `share_file` 工具 + `GET /api/files/share/{key}`（含 1 分钟默认过期）
3. `write_file`/`describe_file` 加 `scope`/`owner_id` 参数
4. 访问控制：列表/搜索/下载/详情按 scope+owner 过滤
5. 前端：文件区切换 + 分享按钮（显示倒计时过期）
6. 测试补充

## 六、已确认（2026-08-20）

1. **「用户」身份来源**：先不管，暂不实现身份识别/归属校验（只落字段，默认 global）。
2. **全局文件分享过期**：全局文件**不过期**；用户文件分享才设 1 分钟过期。
3. **用户文件物理位置**：用**逻辑分区**（`scope`+`owner_id` 字段），不搞目录隔离。
4. **过期后行为**：访问过期链接显示「**已过期**」（不是 404）。
