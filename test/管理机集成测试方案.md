# 管理机集成测试方案

> 2026-10-08。本文是待实现的自动化验收设计，不代表已运行或已通过。
> 目标：验证“存进去、找得到、按 UUID拿对、重启不丢、文件夹往返完整”。

## 1. 测试形态与边界

使用真实 PostgreSQL、正式 server 二进制、HTTP和带鉴权的 MCP SSE。
正常用例只能通过公开入口创建或操作对象；SQL和物理盘读取仅作为独立观察者核对。
故障用例允许显式注入数据库/文件系统状态，但必须标记为状态恢复测试，不能当作真实崩溃实测。
真实进程中断另用屏障精确停在阶段边界，禁止随机等待几毫秒后强杀并声称覆盖某阶段。

计划实现两件测试工具，不增加生产任务框架：

- `test/tools/run-manager-e2e.ps1`：PowerShell 7，构建、独立环境、服务启动/停止/重启、超时和产物保留。
- `test/tools/managerclient/`：Go客户端，MCP/HTTP调用、SQL观察、SHA-256核对、ZIP清单、JSON报告。

测试阶段为 setup → live → restart → faults → verify。屏障与故障注入优先置于测试专用
worker或集成测试替身；若正式 server 必须加屏障，则采用测试构建标签，不能通过普通环境变量开启生产故障点。

## 2. 环境隔离与身份

- 每轮独立测试数据库和独立绝对 DATA_DIR、sourceDir、日志、下载目录；不读取或复用生产文件库。
- 专用端口（启动前检查占用），独立 SECRET_KEY、MCP_API_KEY、管理员密码；输出中隐藏凭据。
- admin、alice、bob 三个主体；HTTP用各自 JWT，MCP用 admin master key及绑定 alice/bob 的 agent key。
- 根目录用现有 `create_directory(path=...)` 创建，记录返回 UUID，不假设目录 ID或文件 UUID。
- 每轮 run_id 放入路径和内容。只断言本轮对象，禁止断言全库文件总数。
- 每个阶段生成持久化 test manifest：主体、请求、目录 UUID、文件 UUID、名称、旧兼容路径、
  内容大小和预期哈希。重启阶段读取清单，不创建新对象来替代丢失对象。
- 结束停止本轮服务，恢复本轮改动的容器状态。数据库、文件和故障证据保留供人工处置，不自动删除。

## 3. 核心不变量（每阶段共享断言）

1. 每份成功回执都能按同一个 UUID取回预期完整字节；同名文件内容和身份不混淆。
2. 正常发布的物理内容 SHA-256 与源内容一致；.partial 不进入取件/目录清单/ZIP内容。
3. SQL 元数据 UUID、目录关联 file_uuid、MCP回执 UUID指向同一对象；目录项没有悬空引用。
4. 同名新建拥有不同 UUID；更新保留目标 UUID；非目标对象的哈希、属性及归属不变。
5. 索引返回 UUID集合，经当前权限复判后与已保存对象相符；目录显示名称可用于找到对应 UUID。
6. API成功不等于“描述已经完成”：描述/索引用有期限的条件轮询，UUID取件与目录挂载分别核对。
7. 任意失败不得回成功，也不得把缺项的归档标为完整；部分导入逐项结果必须与盘库事实吻合。
8. 启动恢复可重复，第二次恢复没有新的动作，不重复创建/归档同一对象。

## 4. 正常链路用例

| 编号 | 操作 | 必须断言 |
|---|---|---|
| N01 | alice MCP create_directory，创建顶层与深层空目录 | 返回合法目录 UUID；MCP list_directory 与 HTTP GET /api/directories/{uuid}一致；空目录重启后存在 |
| N02 | create_child_directory(parent UUID, name)；缺失/错误类型/随机 UUID | 成功子目录的 UUID稳定；非法请求失败，无额外目录或文件；文件 UUID不能冒充目录 UUID |
| N03 | write_directory_file 两次 name=报告.txt，内容 A/B | 两个不同 UUID；列出保留两个同名条目；read_file(uuid)分别返回 A/B；原文件属性不变 |
| N04 | 16个客户端同时向同一目录同名写不同内容 | 16份独立 UUID；每份哈希与所属请求一致，无覆盖，无失败请求被报成功；编号不参与判断 |
| N05 | 目录写入后用搜索 q=报告.txt及内容属性条件查找 | 限时轮询；两个 UUID都可找到；按查询条件区别 A/B；HTTP与 MCP结果对本轮 UUID一致 |
| N06 | read_file同时给 uuid A、路径 B | 建议固定为拒绝不一致参数；不得悄悄读取 B。若暂定 UUID优先，契约与断言必须明确 |
| N07 | 0字节、中文/emoji名称、点文件、无扩展名、多点名称；超过1MB文本；二进制导入 | 0字节成功；完整下载/ZIP哈希一致；MCP文本读取截断标记与长度正确，不拿截断文本作完整哈希 |
| N08 | admin HTTP import 源目录：空目录、两层子目录、PNG、UTF-8、二进制、>5MB文件 | 每项返回 UUID；源内容保留；目录与文件计数准确；大文件用流式下载/ZIP检验；不要求文本写入口支持>5MB |
| N09 | GET /api/directories/{uuid}/zip | ZIP逐项解压校验 CRC及 SHA-256；空目录存在；相对路径正确；同名文件均保留；UUID映射清单无遗漏 |
| N10 | 旧 write_file 文件与新目录上传文件混用 | 原物理布局可按UUID读；旧路径文件在对应目录列表中只出现一次；新文件不出现不透明路径名作为显示名称 |
| N11 | 旧 HTTP/MCP move/copy/modify/delete 操作目录关联文件 | 修改只影响选中 UUID；复制生成新 UUID且目录关联正确；移动后旧目录不再含源UUID；软删不列出/不供下载 |
| N12 | 启动全新环境及再次启动同环境 | migrations幂等；目录UUID和旧文件UUID不变化；恢复日志顺序早于索引重建、事件消费及接收请求 |

N05 特别验证显示名称是否进入实际可查询字段，不能因为标题已写数据库就假设所有索引条件可用。
N11 目前很可能暴露 directory_files 与旧操作入口联动缺口，属于发布阻塞，不降低断言。

## 5. 权限和输入边界

| 编号 | 操作 | 必须断言 |
|---|---|---|
| P01 | 匿名 HTTP请求目录；坏/吊销 MCP key | HTTP 401；MCP连接/调用失败；不能获得目录名、内容或 ZIP |
| P02 | bob 持有 alice目录UUID，列出/新建/导出 | HTTP隐藏为404；MCP拒绝；目录内没有被写入的额外对象 |
| P03 | bob 持有 alice私密文件UUID，调用 read_file | UUID不是授权凭证；拒绝，不能返回字节或绕过路径权限 |
| P04 | public文件跨用户UUID读取；之后改 private再次读取 | public按现有 ACL允许；改 private后拒绝；不能复用旧授权缓存 |
| P05 | 自己目录中关联一个自己无权读取的文件（测试SQL注入） | 列出不泄露文件；完整 ZIP导出失败，不静默漏项后返回200 ZIP |
| P06 | 普通用户尝试 HTTP本地导入 | 403，源文件不读取，目录和盘库不变；admin来源不存在返回可解释失败 |
| P07 | 名称包含 /、\\、..、绝对路径、盘符、NUL；符号链接/特殊文件 | 非法名称拒绝且无残留对象；导入跳过链接并记录失败，不跟随读取库外内容 |
| P08 | 同名目录、目录与同名文件、文件作父路径、Unicode等价名称、超长名称 | 先固定命名契约；目录/文件同名必须可明确区分或统一拒绝，不能因接口不同出现不同规则 |

对于权限更新测试，等待元数据成功更新后再读取；另测授权检查后到真正打开之间的并发变化，
记录实际保证，不能把先查path后按UUID打开视为原子授权。

## 6. 重启和恢复矩阵

先做可确定的注入状态，再做真实强杀。以下位置必须使用测试屏障确认已到达。

| 编号/中断点 | 重启前状态 | 重启后必须满足 |
|---|---|---|
| R01 占位事务提交前 | 无/事务内状态 | 没有残留file_metadata/intake_operations；原路径可新建 |
| R02 占位事务提交后，写入前 | reserved，正式文件不存在 | 只归档本次UUID、释放原路径；旧文件不变 |
| R03 临时文件写了一部分 | reserved + .partial，正式文件不存在 | 不发布半文件；归档失败记录；证据保留 |
| R04 临时文件完整同步但尚未发布 | reserved + 完整.partial | 不把存在临时文件当成功；按当前补偿规则归档，源数据保留 |
| R05 正式路径发布后，CompleteIntake前 | reserved + 完整正式文件 | UUID与内容保留；状态推进stored；二次重启不重复处理 |
| R06 CompleteIntake后，目录关联前 | stored但无directory_files | 必须识别并补关联或明确可恢复失败，不能永久“文件存了、目录里没有” |
| R07 目录关联后，描述事件前 | 正常关联但属性/owner可能未落库 | owner不可被默认公开/无主状态错误暴露；最终描述和索引可恢复 |
| R08 回复成功后强杀 | 内容、关联、状态已确认 | 原UUID读回、目录清单与哈希不变；索引重建仍命中 |
| R09 恢复中途再强杀 | 部分记录已收敛 | 再启动继续剩余项；无重复对象、无误归档stored对象 |

R06/R07 当前机制尚不完备：它们不能标SKIP后作为“恢复通过”，必须计入发布阻塞。
如果没有自动回填开启就无法恢复描述/索引，测试应记录这是配置依赖还是实现缺口。
本轮强杀验证进程崩溃，不证明断电耐久性；断电/文件系统目录同步另做平台专项。

## 7. 故障与并发一致性

- F01 数据库暂不可用：分别发生在 Reserve、Complete、目录关联；用独立DB连接/测试屏障制造，
  不停止其他项目容器。错误回执准确；已发布内容不被覆盖；重启后可收敛。
- F02 目标父目录被普通文件占用、没有写权限、硬链接不支持：成功率可以为0，但不能误报成功。
  权限故障用平台适配方式；磁盘满只在限额测试卷验证，不填满宿主盘。
- F03 客户端取消/断开：服务器若已成功则保存清单；若失败则可恢复。客户端无回复不能推断服务失败。
- F04 同一请求重试：使用同一个请求ID不产生副本；不同ID允许同名副本。当前无请求ID入口，列为待实现阻塞。
- F05 两个进程同时启动恢复：现阶段明确不支持多实例，第二实例应被禁止或该部署形态不可验收。
- F06 导入一项失败：返回失败项但保留成功项UUID；success=false，failed数量与事实一致；重跑不应误报完整成功。
- F07 导出时文件改写/删除、源目录导入时变化：要么输出明确版本的一致包，要么失败；不能混合字节仍宣称一致。
- F08 审计：正常已发布文件不能因为保留.partial而导致“干净库”持续孤儿告警；失败证据与正式物理文件要可区分。
- F09 导出重名碰撞：原文件本来就叫“报告 (UUID).txt”、清单名与用户文件同名；包内名称唯一且映射全量可逆。
- F10 输入解析：畸形UUID、missing字段、错误JSON类型、超限正文；失败不新增状态/文件，错误不泄露内部路径或凭据。

## 8. 运行控制与结果

- 每调用默认15秒；大文件导入/导出单独预算；索引轮询上限30秒并报告最后观察值。
- 健康检查有总deadline；确认响应属于本轮进程，不复用端口上的旧服务。
- 自动重试最多3次，仅瞬态连接/启动检查；断言失败不重跑至绿，不自动重复有副作用的新建。
- 阶段之间保存 manifest并停本轮服务；每次重启使用新日志文件，不能以旧日志的“index rebuilt”认定重建发生。
- 输出 `summary.json`、`manifest.json`、逐阶段server日志、SQL观察摘要、下载 ZIP及哈希清单。
- 状态只用 PASS / FAIL / BLOCKED / NOT_IMPLEMENTED；必要能力的后两者导致总结果非0，不算通过。
- 报告区分接口错误、业务错误、数据不一致、测试环境错误；首次失败保留现场后再处理独立用例。

## 9. 实施与上线门槛

第一批先实现 N01–N05、N08–N12、P01–P07、R02/R03/R05/R08，验证今天的核心存取。
第二批屏障补全R01/R04/R06/R07/R09与F01–F10；按失败证据补齐实现，避免先增加业务功能。

允许“文件夹试用”：正常链路、权限、重启和半文件场景全过，已知限制明确写入报告。
允许“稳定托管”：所有核心不变量及关联/归属恢复、幂等、旧入口联动全过；必要NOT_IMPLEMENTED为0。
本方案不把局部Go单元测试或临时表SQL测试当作完整L4验收结果。
