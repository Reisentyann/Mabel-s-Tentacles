## 简介

这是一个用 Go 开发的 MCP 服务器项目，用于管理、创造、分类文件。聊天机器人风靡全球，铃仙意识到让机器人来管理文件是非常有必要的。但传统 agent 直接管理文件，面临着易出错、没有固定流程、文件一多就找不到的风险。

基于此，我制作了一个面向 agent 的 MCP 文件管理器：agent 就好好聊天，文件方面的事情就交给纯粹的理性分析吧。

**特色：** 这个项目与其他项目不同的是，它正在开发一个相当特殊的文件描述机，我配置了大量描述字段，比如这个文件有多少字符，文件中的标题有哪些，有多少表格，英文很多吗，最长的一句话有多长……
设计意图是，尽可能完整的描述这个文件，并且想办法设计量化标准，以便于agent可以模糊查询某些文件。
对此，描述机，索引机，管理机是必要的。

至于为什么选 Go——因为 Go 的体感相当优雅。

技术栈：Go（单体后端，同进程提供 MCP 与 HTTP API）· Vue 3 · PostgreSQL · Docker Compose。

## 功能

**MCP 工具**（agent 调用）：

| 工具 | 功能 |
|---|---|
| `write_file` / `read_file` | 写文件（写完自动分析，回执带文件编号和下载链接）/ 读文件 |
| `modify_data_file` | 往文件里追加内容，或整段覆写 |
| `move_file` | 移动 / 重命名：文件编号、描述、归属都不变，改个名而已 |
| `list_data_files` | 分页列出文件，可按关键词过滤，标出哪些还没写描述 |
| `describe_file` | 给文件写描述、标签（机器算出来的字段不许动，只有描述区开放） |
| `analyze_file` | 让系统把文件重新读一遍、刷新描述字段（比如 agent 绕过系统直接改了文件之后） |
| `copy_file` | 复制文件（内容连同描述一起搬，副本归操作者，并记一笔"复制自哪"） |
| `execute_command` / `get_results` | 执行 Shell 命令（60s 超时）/ 查询历史执行结果 |

**文件存在哪**：agent 只管用顺手的路径（比如 `小说/第一章.txt`），文件在磁盘上的实际位置由系统随机分配——盘面上全是随机文件名，看不出任何文件是什么、在哪。就算有人摸到了服务器磁盘，也猜不到文件放哪。

**多用户**：每个用户有自己独立的空间，你写你的 `笔记.txt`、我写我的 `笔记.txt`，互不干扰。要读别人公开的文件，加个前缀 `~用户名/文件名` 就行；别人标了私密的文件，除了主人和管家谁都动不了。文件默认公开，谁都能用。

**Web 前端**（人类使用，一张页面的管理台）：

| 功能 | 说明 |
|---|---|
| 文件树 | 左侧目录树，点目录看里面的文件 |
| 文件列表与搜索 | 路径 / 类型 / 大小 / 更新时间；关键词、标签、描述全文搜索 |
| 文件详情 | 基本信息、描述标签、机器算出来的全部量化字段（按 文本/代码/图片/语义 分组）、来龙去脉（复制自哪、移动自哪） |
| 文件操作 | 下载、移动、复制、重新分析，页面上直接点 |
| 统计 | 文件数、总大小、目录数、类型分布 |

深色书房主题。管理台用管理员账号登录（不开放注册——这是给自己 agent 配套的自用工具，不是公开服务）。

**已经做好的**：

| 功能 | 说明 |
|---|---|
| 文件描述引擎 | 自动读文件内容，产出 90 多个量化字段：语言、行数、表格数、最长句、英文占比、是代码还是文档、图片色调…纯计算，不需要 AI 参与，结果永远一致 |
| 字段查询 | 这些字段全部可以当搜索条件用——"帮我找中文的、带表格的、100 行以上的文件"这种模糊需求直接查 |
| 文件存取 | 上面说的：路径进、随机名出，位置不可猜 |
| 改动自动发现 | 定期巡检磁盘，文件内容变了（哪怕是被绕过系统直接改的）就自动重新分析、更新记录；连续几轮找不到的文件自动标记删除（不真删，记录还在） |
| 读文件缓存 | agent 反复读的小文件走内存缓存，不反复磨磁盘 |
| 限时下载链接 | agent 分享出去的下载链接只对这一个文件有效，一天后自动失效——链接被转发也不怕（曾经的全局令牌方案已因此退役） |
| 来龙去脉 | 复制记"复制自哪"，移动记"移动自哪"，文件详情里直接看 |
| 单页管理台 | 上面前端表格里那些 |
| 端到端测试 | 从"agent 写文件"到"多用户互不干扰"整条链路有自动化测试跑着，改坏了立刻知道 |

**还没做的**：

| 功能 | 说明 |
|---|---|
| 语义描述 | 现在只有机器算的事实字段，"这文件讲了什么"这种理解性描述还没接 AI |
| 对话标识 | QQ 里谁让 agent 存的文件，就自动归到谁名下（现在归统一的管家空间） |
| 谱系图 | 来龙去脉数据已经有了，画成图还没做 |
| 删除入口 | agent 主动删文件（自动软删已有，主动删还没做） |
| 重名文件保护 | 现在同一个用户写同名文件会**直接覆盖旧内容**，没有任何提示——万一 agent 手滑就是一场事故；想改成更安全的处理：覆盖前确认、自动改名留档、或保留旧版本 |
| 游戏室 | 路径分区留好了（`game/` 开头的自动归档），玩法还没做 |
| 真随机机 | 想法，待定 |

还有更多的功能。

## 快速开始

### 生产部署（单二进制 + systemd）

```bash
# 服务器上（linux/amd64，纯 Go 无 CGO——本地交叉编译即可）
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -o mabel-server ./cmd/server

mkdir -p /opt/mabel/{data,logs,web}
# 前端：pnpm build 后把 frontend/dist/* 放入 /opt/mabel/web（服务端自带 SPA 托管）
# 配置 /opt/mabel/.env（管理员账号、强随机的 SECRET_KEY 与 MCP_API_KEY、
# DATABASE_URL 指向本机 postgres、可选 ACCESS_TOKEN 供 agent 分享直下链接），
# 填法与 systemd 单元模板见部署指南第 5 节
```

- MCP 端点：`http://<内网>:18001/sse`（要暴露到公网就走反向代理 + 域名，代理配置里记得关缓冲，不然 agent 的长连接会被卡住）
- 管理页：同端口 `/`（仅管理员账号，建议只在内网或隧道访问）
- 本地开发（Windows / PowerShell 7）：

```powershell
# 1. 先把数据库拉起来（只跑 postgres 一个容器即可）
docker compose up -d postgres

# 2. 一键编译后端(8080) + 启动前端 dev(5173)
./start-dev.ps1
```

AstrBot 等 MCP 客户端的接入配置，见[部署指南](部署指南.md)第 5 节。
