# 混沌机（chaos-go）

> 一句话定位：核心是与文件无关的娱乐功能集合；文件型产出由 MCP 装配层交给管理机。
> 状态：已实现（2026-09-23）：`mabel_quote`（梅贝尔台词）、`pseudo_random`（伪随机机）、
> `true_random`（真随机机，默认休眠保留——待找到可靠真随机源再点亮）、`jm_comic`
>（JMComic 查询/下载；ZIP 下载由 MCP 装配层交给管理机入库）。
> 架构形状见 `架构设计.md`，本文只管混沌机这一层。

## 1. 定位与边界

**形态**：仓库根目录的独立 Go 模块 `chaos-go/`，与 describer-go / indexer-go /
manager-go 同级，是一个纯库。

**边界**：

1. **核心与纯娱乐组件零 DB**：`mabel_quote` / `pseudo_random` 只做内存计算；
   `true_random` 的网络熵源是**可选注入**的，见第 4 节，不配置就不联网且**取数失败不回退**。
   `jm_comic` 是文件型例外：它调用 Python 下载器产生本地归档，但不写 Mabel 的
   data 目录或 PostgreSQL；归档由 MCP 装配层交给管理机。
2. **核心零兄弟依赖**：`chaos-go` 不 import 其他业务模块（唯一的例外是
   `cmd/chaos` 命令行自己）。MCP 装配层可以为会产生文件的组件提供适配钩子；
   `jm_comic` 的入库适配位于 `mcp-server-go`，不污染纯库边界。
3. **组件自注册**：每个娱乐功能自成一个**文件夹**，`init()` 里登记进注册表；
   装配层不认识任何具体组件，只认识接口。
4. **随机源收口**：共用 `Chaos` 实例的随机源（并发安全）与可选真随机熵源；
   测试用 `New()` 建独立实例，避免污染全局。

## 2. 模块结构

一个组件一个文件夹，文件名全小写无符号：

```
chaos-go/
├── chaos.go        混沌机核心：Chaos 实例 + 随机源 + EntropySource 接口 + Default() 单例
├── feature.go      Feature 接口 + Register 注册表 + 参数助手（IntParam/StrParam/BoolParam）
├── all/
│   └── all.go      blank import 各组件（触发自注册）
├── mabel/          组件·梅贝尔台词
│   ├── mabel.go    功能 mabel_quote + 分组解析
│   └── lines.txt   台词库（go:embed；正本 docs/梅贝尔全文本.txt）
├── pseudorandom/   组件·伪随机机
│   └── pseudorandom.go  功能 pseudo_random（PRNG）
├── truerandom/     组件·真随机机（默认休眠保留）
│   ├── truerandom.go  功能 true_random
│   ├── lfdr.go        熵源：lfdr.de（ID Quantique 量子硬件）
│   ├── jinan.go       熵源：济南 DIQRNG 信标
│   └── anu.go         熵源：ANU（旧端点已退役）
└── cmd/
    └── chaos/      命令行：按功能名运行
```

## 3. 组件注册表（可扩展性的核心）

`feature.go` 定义接口，任何娱乐组件实现四个方法即可：

```go
type Feature interface {
	Name() string                                    // 对外唯一名 = MCP 工具名
	Description() string                             // 给 agent 看的功能说明
	Params() []Param                                 // 入参声明（可为空）
	Run(c *Chaos, p Params) (map[string]any, error)  // 执行 → 结果体
}
```

- **自注册**：组件 `init()` 调 `chaos.Register(f)`；空名/重名在装配期直接 panic。
- **顺序稳定**：`Features()` 按注册序返回（同 import 顺序确定）。
- **参数声明**：`chaos.Param{Name, Type, Description, Required, Default}`，
  `Type` 取 `ParamString` / `ParamNumber` / `ParamBool`。
- **参数读取**：MCP 传入的 JSON 归一到 `Params`（数字可能是 `float64`）——
  用 `chaos.IntParam` / `StrParam` / `BoolParam` 取值，缺失吃默认值。
- **随机原语**：组件共用实例方法 `c.IntN(n)` / `c.Shuffle(n, swap)`（并发安全）。

## 4. 现有组件

### `mabel_quote` —— 梅贝尔台词

- **台词库**：`mabel/lines.txt`（`//go:embed` 打进二进制，部署零额外文件）。
- **分组规则**：按空行切块，每个非空行块 = 一段台词（可能多行，即一个 group）。
  清掉转录残留：RPG Maker 控制码 `\c[n]`、转义叹号 `\!`。实测 380 组。
- **取样**：默认随机 1–5 段、互不重复；`count` 可指定 1–5。
- **返回**：`{"success": true, "count": N, "lines": [...], "hint": "..."}`，
  `lines` 已含 `「」` 引号，agent 原样转发即可。

### `pseudo_random` —— 伪随机机

- **数据源**：混沌机实例的伪随机数发生器（`math/rand/v2` 的 PCG），快、本地、
  零外部依赖、给定种子可复现。**娱乐用，不用于密码学保密**。
- **参数**：`count`（个数，1–100，默认 1）、`min`/`max`（闭区间，默认 1–100）。
- **返回**：`{"success": true, "source": "prng:math-rand-v2", "min": L, "max": H, "values": [...]}`。

### `true_random` —— 真随机机（物理量子层面，默认休眠保留）

- **数据源**（`chaos.true_random.source`，可切换）：
  - `off`（默认）：不启用（休眠保留——待找到可靠真随机源再点亮）；
  - `lfdr`：`lfdr.de`，后端 ID Quantique 量子随机数硬件，公开免费无 key，
    **每次调用取新值**（但公共免费源不保证牢靠）；
  - `jinan`：济南 DIQRNG 信标（器件无关、安全性最高），但按分钟发布脉冲、
    实测脉冲时间戳偏旧（同一脉冲内重复取数同值）；
  - `anu`：澳国立真空量子涨落（旧端点已退役，暂不可用）。
- **参数**：`count`（字节数，1–32，默认 8）。
- **返回**：`{"success": true, "source": "quantum:de-lfdr", "bytes": N, "hex": "...", "meta": {...}}`。
- **铁律：不回退**。熵源未配置或取数失败，一律返回 `success:false` + 原因，
  **绝不拿伪随机/OS 随机冒充量子随机**。

### `jm_comic` —— JMComic 查询与下载

- `action=view` 查询本子详情；`action=download` 下载 album/photo。
- 默认 `format=zip`。Python 下载器先生成本地归档，MCP 装配层随后调用
  `manager.Manager.ImportFile(logicPath, sourcePath)`：管理机负责占位、UUID
  派生物理路径和文件转移，混沌机不直接拼接 `data/` 路径。
- 导入成功后提交 `core.KindWrite` 事件，由编排机异步完成描述、元数据落库和
  索引喂食，并返回 Mabel 短链/下载票据。
- 导入失败会作为 MCP 工具失败返回并写入操作记录，不再只打印告警后伪装成功。
- `chaos-go` 仍保持纯库；文件接线只存在于 `mcp-server-go/internal/tools/chaos`。

## 5. 新增一个组件（两步，不动装配层）

1. 新建文件夹 `chaos-go/<组件名>/`，实现 `Feature` 并在 `init()` 注册：

```go
// 文件：chaos-go/dice/dice.go —— 混沌机组件·掷骰
package dice

import (
	"fmt"

	"github.com/Reisentyann/Mabel-s-Tentacles/chaos-go"
)

func init() { chaos.Register(diceFeature{}) }

type diceFeature struct{}

func (diceFeature) Name() string { return "roll_dice" }

func (diceFeature) Description() string { return "Roll a D20. Optional param sides (default 20)." }

func (diceFeature) Params() []chaos.Param {
	return []chaos.Param{
		{Name: "sides", Type: chaos.ParamNumber, Description: "Die faces, default 20.", Default: 20},
	}
}

func (diceFeature) Run(c *chaos.Chaos, p chaos.Params) (map[string]any, error) {
	sides := chaos.IntParam(p, "sides", 20)
	if sides < 2 {
		return nil, fmt.Errorf("sides 至少为 2")
	}
	return map[string]any{"success": true, "result": 1 + c.IntN(sides)}, nil
}
```

2. 在 `chaos-go/all/all.go` 加一行 blank import（触发自注册）→ `go test ./...`。
   重启服务后 MCP 自动多出 `roll_dice` 工具——`mcp-server-go` 不用动。

## 6. 测试

- 混沌机：`Set-Location chaos-go; go test ./...`
  - 核心：注册表机制、参数归一、熵源注入（`feature_test.go`）；
  - mabel：库解析、段数/去重/并发、自注册（`mabel/`）；
  - truerandom：组件成功/失败不回退、济南客户端解析/元数据/服务错（`truerandom/`，
    用 `httptest` 假服务器，不真连网）。
- 装配层：`Set-Location mcp-server-go; go test ./internal/...`
- 按 `test/测试规则.md` 的回归触发清单，混沌机改动属 L1（无 DB）。

## 7. 接线（装配层要做的事）

```text
require github.com/Reisentyann/Mabel-s-Tentacles/chaos-go v0.0.0
replace github.com/Reisentyann/Mabel-s-Tentacles/chaos-go => ../chaos-go
```

- `mcp-server-go/internal/tools/chaos/chaos.go`：blank import `chaos-go/all`
  （触发组件自注册）+ 遍历 `Features()` 泛化挂载（按 `Params()` 动态生成同名工具）；
  `jm_comic` 的归档结果在这里调用 `Manager.ImportFile`，再提交 `KindWrite` 事件。
- **真随机熵源注入**：读配置 `chaos.true_random.{source,endpoint,timeout_seconds}`，
  `source=lfdr|jinan|anu` 时构造对应熵源注入 `chaos.Default()`；`off`（默认，休眠）不注入。
  环境变量覆盖：`CHAOS_TRUE_RANDOM_SOURCE` / `CHAOS_TRUE_RANDOM_ENDPOINT` /
  `CHAOS_TRUE_RANDOM_TIMEOUT`。纯库组件不依赖 `manager-go`；只有 `jm_comic` 的 MCP
  装配钩子显式调用 `Manager.ImportFile`。
- `mcp-server-go/Dockerfile`：构建上下文 = 仓库根，两段 COPY 带 `chaos-go`。

命令行：`go run ./cmd/chaos [功能名] [k=v ...]`，真随机需 `-source lfdr|jinan|anu`。
