# 混沌机（chaos-go）

> 一句话定位：与文件无关的娱乐功能集合——描述机/索引机/管理机管文件，混沌机管好玩。
> 状态：已实现（2026-09-11），首个功能 `mabel_quote`（梅贝尔台词）。
> 架构形状见 `架构设计.md`，本文只管混沌机这一层。

## 1. 定位与边界

**形态**：仓库根目录的独立 Go 模块 `chaos-go/`，与 describer-go / indexer-go /
manager-go 同级，是一个纯库。

**四条边界**：

1. **零 IO、零 DB**：不碰磁盘、不碰 PostgreSQL——只做内存里的随机与娱乐。
2. **零兄弟依赖**：不 import 其他业务模块（唯一的例外是 `cmd/chaos` 命令行自己）。
   它和文件链路完全正交，删掉混沌机，文件系统照常运转。
3. **功能自注册**：每个娱乐功能自成一个文件，`init()` 里登记进注册表；
   装配层不认识任何具体功能，只认识接口。
4. **随机源收口**：所有功能共用一个 `Chaos` 实例的随机源（并发安全），
   测试用 `New()` 建独立实例，避免污染全局。

## 2. 模块结构

```
chaos-go/
├── chaos.go      混沌机实例：Chaos（独立随机源 math/rand/v2）+ Default() 单例
├── feature.go    Feature 接口 + Register 注册表 + 参数助手（IntParam/StrParam/BoolParam）
├── mabel.go      功能·梅贝尔台词（embed 台词库 + 分组解析 + 注册 mabel_quote）
├── data/
│   └── mabel_lines.txt   台词库（docs/梅贝尔全文本.txt 的编译内置副本）
└── cmd/
    └── chaos/    命令行：go run ./cmd/chaos 即打印随机台词
```

## 3. 功能注册表（可扩展性的核心）

`feature.go` 定义接口，任何娱乐功能实现四个方法即可：

```go
type Feature interface {
	Name() string                                    // 对外唯一名 = MCP 工具名
	Description() string                             // 给 agent 看的功能说明
	Params() []Param                                 // 入参声明（可为空）
	Run(c *Chaos, p Params) (map[string]any, error)  // 执行 → 结果体
}
```

- **自注册**：功能文件 `init()` 调 `Register(f)`；空名/重名在装配期直接 panic，
  错误尽早暴露，不留到运行期。
- **顺序稳定**：`Features()` 按注册序返回（同 import 顺序确定）。
- **参数声明**：`Param{Name, Type, Description, Required, Default}`，
  `Type` 取 `ParamString` / `ParamNumber` / `ParamBool`。
- **参数读取**：MCP 传入的 JSON 归一到 `Params`（`map[string]any`，
  数字可能是 `float64`）——用 `IntParam` / `StrParam` / `BoolParam` 取值，缺失吃默认值。

## 4. 现有功能

### `mabel_quote` —— 梅贝尔台词

- **台词库**：`docs/梅贝尔全文本.txt`（正本），编译副本 `chaos-go/data/mabel_lines.txt`，
  用 `//go:embed` 打进二进制——部署零额外文件。
- **分组规则**：按空行切块，每个非空行块 = 一段台词（可能多行，即一个 group）。
  逐行右裁空白后拼回，最后清掉转录残留：RPG Maker 控制码 `\c[n]`、转义叹号 `\!`。
  实测 380 组。
- **取样**：默认随机 1–5 段、互不重复；`count` 参数可指定 1–5（超出夹到 5，
  超过库容量取全库）。
- **返回**：`{"success": true, "count": N, "lines": [...], "hint": "..."}`，
  `lines` 已含 `「」` 引号，agent 原样转发即可。

命令行（不经 MCP 直接用）：

```powershell
Set-Location chaos-go
go run ./cmd/chaos        # 随机 1-5 段
go run ./cmd/chaos -n 3   # 指定 3 段
```

## 5. 新增一个功能（两步，不动装配层）

1. 在 `chaos-go/` 新建一个文件，实现 `Feature` 并在 `init()` 注册：

```go
// 文件：chaos-go/dice.go —— 混沌机功能·掷骰
package chaos

import "fmt"

func init() { Register(diceFeature{}) }

type diceFeature struct{}

func (diceFeature) Name() string { return "roll_dice" }

func (diceFeature) Description() string {
	return "Roll a D20. Optional param sides (default 20)."
}

func (diceFeature) Params() []Param {
	return []Param{
		{Name: "sides", Type: ParamNumber, Description: "Die faces, default 20.", Default: 20},
	}
}

func (diceFeature) Run(c *Chaos, p Params) (map[string]any, error) {
	sides := IntParam(p, "sides", 20)
	if sides < 2 {
		return nil, fmt.Errorf("sides 至少为 2")
	}
	return map[string]any{"success": true, "result": 1 + c.intn(sides)}, nil
}
```

2. `go test ./...`。重启服务后 MCP 自动多出 `roll_dice` 工具——
   `mcp-server-go` 的 `internal/tools/chaos`、`internal/tools/all/all.go` 都不用动。

> 需要给命令行也加入口时，才改 `cmd/chaos/`（各功能是否上 CLI 由功能自己决定）。

## 6. 测试

- 混沌机自身：`Set-Location chaos-go; go test ./...`
  覆盖台词库解析（组数/非空/无控制码残留）、随机段数与去重、默认随机范围、
  上限夹取、并发安全、注册表查找/派发、参数归一。
- 装配层：`Set-Location mcp-server-go; go test ./internal/...`
- 按 `test/测试规则.md` 的回归触发清单，混沌机改动属 L1（无 DB）。

## 7. 接线（装配层要做的事）

混沌机本身零依赖，装配三层：

```text
require github.com/Reisentyann/Mabel-s-Tentacles/chaos-go v0.0.0
replace github.com/Reisentyann/Mabel-s-Tentacles/chaos-go => ../chaos-go
```

- `mcp-server-go/internal/tools/all/all.go`：blank import 工具面包；
- `mcp-server-go/internal/tools/chaos/chaos.go`：遍历 `Features()` 泛化挂载
  （每个功能按 `Params()` 动态生成同名 MCP 工具，不写死任何功能）；
- `mcp-server-go/Dockerfile`：构建上下文 = 仓库根，两段 COPY 记得带上 `chaos-go`。
