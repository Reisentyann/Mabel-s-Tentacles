# 三机结构（描述机 / 索引机 / 管理机）

> 本文是三机的**内部结构地图**：每个模块里有哪些文件、各自干什么、关键接口长什么样、数据怎么流。
> 为优化工作提供定位依据。字段定义见 `元数据字段说明.md`，架构决策与铁律见 `架构设计.md`，
> 本文不重复其内容，只描述"机器内部长什么样"。
> 基线：2026-11-16 代码现状。代码路径相对仓库根。

## 0. 三机总览

| 模块 | 一句话定位 | 形态 | 依赖 |
|---|---|---|---|
| `describer-go/` | 字节进、事实出（90+ 量化字段） | 纯库，零 IO 零 DB（读文件由调用方 Loader 提供） | goexif / x/image / x/text；common 仅 cmd/verify 用 |
| `indexer-go/` | 字段条件 → uuid 集合 | 纯库，进程内内存索引，sink 零出调用 | **零依赖**（连 common 都不 require） |
| `manager-go/` | 文件位置与谱系的唯一知情者 | 库 + 门面，Store 最小面注入（依赖倒置） | common + describer-go（同级 replace） |

依赖方向（单向，无环）：

```
装配层 mcp-server-go（main.go 构造并注入一切）
   ├── core/ 编排机 ──┬── describer.Analyze / MergeResults / IsStale
   │                  ├── indexer.Query / Update / Rebuild
   │                  └── manager 各域方法
   ├── manager ──→ describer（updater 域重分析）
   │        └──→ IndexSink 接口（本地定义，装配层把 indexer 实例注入）
   └── repo ──→ 实现 manager.Store（manager 不 import repo，不写 SQL）
```

- manager **不 import indexer**：`IndexSink` 是 manager 包内自定义的单方法接口，indexer 实例由装配层注入。
- describer **不认识文件在哪**：`Input.Path` 只用于扩展名/文件名模式判定，物理位置归 manager。
- indexer **不认识内容**：只吃 attributes 快照（`map[string]any`），DB 是事实源，索引是派生缓存。

### 1.2 引擎根包（describer.go）

核心契约：

```go
type Descriptor interface {
    Family() string                 // 家族名（basic/text/code/image）
    FamilyVersion() int             // 算法版本：加字段/改输出/删字段 +1，纯重构不动
    Supports(path string, head []byte, b Basic) bool  // 路由判定
    SPNamespaces() []string         // 本家族负责的 sp-cod- 前缀（整族替换时清旧键）
    Analyze(in Input, full []byte) (attrs map[string]any, sp map[string]string)
}
```

- **输入** `Input{Path, Head, Full, Size, MTime, ExtMime}`：Head 前 512B；Full 可为 nil，
  由 `Loader func() ([]byte, error)` 惰性加载（调用方实现，出错则需全量的插件被跳过）。
- **预算引擎强制**：`MaxHeadBytes = 512`、`MaxFullBytes = 5MB`，在 Analyze 入口统一截断，
  调用方传全量也安全（manager 的入库上限、buffer 单条目上限都引用此常量，单一来源）。
- **注册表**：各插件 `init()` 调 `Register` 自注册，`all/all.go` 集中 blank import 点亮。
  `CurrentVersions()` 导出 family→ver 表，供 manager updater 做 IsStale 的 curVer 入参。
- **Analyze 编排**（注册序，确定）：
  1. basic 恒跑（只认首个注册，防双跑），产出路由事实 `Basic{Mime, Textish}`；
  2. 其余插件 `Supports` 路由，命中者**共享一次全量加载**（needFull 惰性 + 5MB 截断）；
  3. SP 自由字段由引擎统一加 `sp-cod-` 前缀；
  4. **已跑即入列**：零产出家族以空 Attrs 入列（MergeResults 借此整族清旧键，防陈旧残留）；
     全量加载失败的家族不入列（旧键保留，重跑时机归 IsStale）。
- **panic 隔离**：`safeAnalyze`/`safeSupports` 逐插件 recover，单插件崩溃不拖垮整轮。
- 产出键只允许 `cod-<family>-<字段>`（代码字面量封闭集）与 `sp-cod-<自由字段>`。

### 1.3 插件家族现状

| 家族 | 版本 | 路由（Supports） | 产出概要 |
|---|---|---|---|
| basic | 3 | 恒 true | mime / mime-match / mtime / textish / executable / entropy / name-pattern（7 键） |
| text | 5 | `b.Textish` | 62 个 extractor + partial 标记；解码链 UTF-16(BOM)→UTF-8→GBK(零替换符)→latin-1 |
| code | 3 | Textish 且扩展名命中 codeLangs（go/py/js/ts/java/c/cpp/rs/…23 种） | lang / imports / todo-count / generated / package / func-count / comment-ratio / test-file / license / exported-names + Go AST 定位 |
| image | 3 | `b.Mime` 前缀 `image/` | 尺寸/朝向/百万像素 + ≤128×128 确定性降采样 → 亮度/对比/调色板/色系/P2 画像；EXIF 与 PNG 文本块走 sp-cod-* |

**text 家族的注册表模式**（加字段的标准落点）：

- `textCtx`（ctx.go）：解码/分行/切 rune/字符分类计数**一次构造**，全 extractor 共享；
  `Quant()`/`FP()` 两组计数惰性预计算（首次访问才遍历，单线程无锁）。
- `extractor{name, needs, extract}`（extractor.go）：一个字段一个提取器；`needs` 路由
  （nil=恒算），`extract` 返回 nil 表示该文件不产此键。注册序即产出序。
- 主编排 text.go 稳定不动；加字段只动分类文件 + 注册表一行。

### 1.4 llm 模型轨（llm/）

与 cod 轨完全分离，**不参与 Analyze、不注册 Descriptor**：

- `gate.go`：受控词表——固定字段 7 个（semantic-type/tone/characters/action/style/summary/source），
  semantic-type 枚举 12 值；`sp-llm-*` 自由放行；其余前缀拒绝。`SanitizeLLM` 为兼容层。
- `store.go`：`LLMStore` 是 llm 轨**唯一写入口**（Set/SetMany/Delete/Commit）：
  - cod-* / sp-cod-* 绝对只读，Set/Delete 一律拒绝；
  - llm-source / llm-at 审计字段系统专属，Commit 统一盖戳（模型不可伪造）；
  - 值为 nil（JSON null）= 删除墓碑；
  - 被拒操作以 `Rejection{Key, Op, Reason}` 回传（人话原因，教育模型）；
  - Commit：先删后写再盖戳，无变更原样返回（避免元数据行无谓抖动）。

### 1.5 合并与陈旧判定

- `MergeResults(existing, results, now)`（merge.go）：逐家族**整族替换**——
  清 `cod-<family>-*` 旧键 + SPPurge 前缀旧键 → 写新键 → 刷新 `cod-<family>-ver/-at`。
  llm-* / sp-llm-* 原样保留（模型轨不走这里）。读-改-写持久化由调用方负责。
- `IsStale(attrs, family, curVer, storedChecksum, curChecksum, mtime)`（stale.go）：
  任一命中即陈旧——① 缺 ver ② ver < curVer ③ checksum 漂移 ④ mtime 晚于 at。
  兼容 JSON float64 / int / 字符串数字。
- `AttrsFromJSON` / `JSONFromAttrs`：attributes 的 JSON 往返（绝不返回 nil map）。

### 1.6 扩展点

- **text 加字段**（extractor.go 注释钉死的五步）：分类文件写 extractXxx → 注册表加一行 →
  字段字典加条目 → test/测试规则.md 断言表加一条 → FamilyVersion +1。
- **加新家族**：建子包实现 Descriptor + init Register → all/all.go 加一行 blank import。
- **改算法输出**：FamilyVersion +1，存量由 manager updater 回填重算。

## 2. 索引机 indexer-go

### 2.1 目录结构

```
indexer-go/
├── indexer.go   接口与类型：Op / Condition / Expr / Stats / FieldKind / FieldInfo / Indexer
├── expr.go      布尔表达式树：Leaf / And / Or / Not + Leaves（SQL 降级判定）
├── bucket.go    三型桶数据结构 + 归一化原语（keyOf/toFloat/sliceOf/rangeOf）
├── mem.go       进程内内存实现：memIndexer（桶 + attrs 镜像两层）
├── expr_test.go / mem_test.go
└── go.mod       零依赖
```

布局范式 ≈ stdlib hash：接口/实现分离，将来外部化换实现不动调用方。

### 2.2 接口（indexer.go）

```go
type Indexer interface {
    Query(expr Expr) ([]string, error)              // 条件 → uuid 集合（升序，确定）
    Update(uuid string, old, new map[string]any)    // 喂食：new 为完整快照；nil/空 = 整体移除
    Rebuild(all map[string]map[string]any) error    // 启动全量重建（DB 载入）
    Stats() Stats                                   // 自省：fields/keys/mounts
    Catalog() []FieldInfo                           // 字段目录：桶型/取值/值域（agent 发现接口）
}
```

- **Op 八种**：eq / in / gt / lt / range / ne / exists / contains。
  ne/exists/contains 是扫描型（走 attrs 镜像），其余走桶快路径。
- **FieldKind 三型**：enum（标量）/ num（数值）/ multi（数组），决定字段支持的 Op 集。
- `CatalogValueLimit = 50`：目录取值列表截断保护（目录是发现用的，不是全量导出）。
- 空表达式 = 空集（不报错、不当全集）；从未挂过值的字段 = 无命中；桶型与 Op 不符报错（上层降级 SQL）。

### 2.3 表达式树（expr.go）

`Expr{Cond, And, Or, Not}` 恰好一种形态有效，任意嵌套。
构造器 `Leaf/And/Or/Not`；`IsEmpty`（空集短路）、`Count`（叶子数，诊断用）、
`Leaves()`（纯 And 树摊平成 []Condition，供 SQL 降级判断；遇 Or/Not 返回 ok=false）。

### 2.4 三型桶（bucket.go）

| 桶型 | 结构 | 查询 | 适用 |
|---|---|---|---|
| enumBucket | `map[值]→uuid 集合` | eq 直查 O(1) / in 并集 | 语言、eol、bool、枚举 |
| multiBucket | 同构，一 uuid 多挂 | 同上（任一元素命中即整文件命中） | tags、structure、top-keywords 等数组 |
| numBucket | `(float64, uuid)` 有序切片 | 二分 lower/upperBound → eq/gt/lt/range/in | 一切数值字段（插入 O(n) 挪位，个人库量级足够） |

- 桶型由字段**首个可索引值**自动决定（数值→num / 数组→multi / 标量→enum），加字段=加桶零配置。
- 归一化原语挂载/查询两侧共用：int 3 与 float64 3 同键；数字字符串可入数值桶。
- 幂等：add 同 (uuid,值) 重复挂载 no-op；remove 不存在的挂载 no-op。
- 脏值 best-effort：nil / 对象 / 纯对象数组（如 palette）静默跳过——DB 是事实源，不值得中断喂食。
- 键值桶 eq 命中返回桶内部集合（只读约定）；num 桶 collect 新建集合。

### 2.5 内存实现（mem.go）

```go
type memIndexer struct {
    mu      sync.RWMutex
    buckets map[string]bucket         // field → 桶（快路径）
    attrs   map[string]map[string]any // uuid → 原始 attributes 镜像（扫描路径）
}
```

- **两层结构**：桶只挂可索引值，缺键信息桶里不可见——ne/exists/contains 与 Not 补集
  都需要 attrs 镜像（内存翻倍，个人库量级可接受）。
- **并发**：Query/Catalog/Stats 读锁；Update/Rebuild 写锁。
- **Query**：递归 eval（And=交集，从最小集起步早退；Or=并集；Not=对镜像全集取补），结果升序。
- **Update**：以**自身现态**做 diff（调用方 old 仅兼容参数，可能过期）；cloneAttrs 深拷贝隔离输入；
  值没动不碰桶；new 空 = 整体移除（删除路径）。镜像同步覆写（含不可挂桶的键——exists 语义）。
- **Rebuild**：清空全部桶与镜像后重挂；持写锁期间查询等待；无失败路径（error 留给将来外部化）。

### 2.6 喂食与降级（外部接线，不在本包）

- 实例由装配层 main.go 构造，同时注入编排机 core/（T1 事件 / describe / copy 喂食 + 检索门面）
  与管理机（T2/T3 喂食）——七条持久化路径全收口。
- 启动 RebuildIndex 全量重建；失败仅告警，检索降级 SQL（mcp-server-go/internal/search/sql.go），服务照常起。
- 检索链路：`q.Attributes → Index.Query → uuid 批量取件（manager.LocateMany）→ 内存复判/排序分页`；
  文本/标签/含软删仍走 SQL；空集是合法答案不降级。
- execute_command 直改文件的绕口：索引不管，靠 manager updater 的 IsStale checksum 漂移对账兜底（最终一致）。

### 3.2 门面与注入（manager.go / store.go / errors.go）

```go
func New(st Store, dataDir string, sink IndexSink,
         extMime func(path string) string, dl DownloadConfig) *Manager
```

| 注入项 | 来源 | 说明 |
|---|---|---|
| `Store` | 装配层 repo 适配器（manager_adapter.go） | 元数据读写契约；manager 编排它，不拥有它（不写 SQL） |
| `dataDir` | 配置 | 文件系统根（updater 读盘 / placement 派生） |
| `IndexSink` | indexer 实例 | 包内单方法接口 `Update(uuid, old, new)`；nil = 不喂食 |
| `extMime` | 装配层 | 扩展名→MIME 推导；nil = cod-basic-mime-match 不产出 |
| `DownloadConfig{Secret, BaseURL}` | 装配层 | 空 = 下载未启用 |
| `SetMetaUpdateRunner` | 编排机 updateMu | 可选钩子：T2/T3 的读-改-写-喂索引在同一串行临界区 |

- `Store` 契约四组方法：查询（ListMetaPage/All、GetMeta/ByUUID/ByUUIDs、ReverseCopiedFrom）、
  重分析巡检（UpsertMeta、MarkMissing/ResetMissing、SoftDeleteMeta）、
  入库（ReserveMeta、CompleteIntake、ArchiveFailedIntake、ListPendingIntakes、IsIntakePending）、
  目录移动（CreateDirectory、ListDirectoryPaths、DirectoryExists、MoveMeta）。
- 可选扩展接口（类型断言探测）：`DirectoryStore`（UUID 目录）、`UUIDMoveStore`、
  `MoveRecoveryStore`、`AnalysisName`（目录显示名优先于逻辑键做分析）。
- 哨兵错误：`ErrNotFound`（无行）/ `ErrDeleted`（软删）/ `ErrGhost`（行在盘无）/
  `ErrPending`（未发布）/ `ErrInvalidPath` / `ErrDirectoryExists` / `ErrKeyExists`（含软删占位）。

### 3.3 域清单

| 域 | 主要方法 | 职责与语义 |
|---|---|---|
| intake | Write / WriteBytes / ImportFile | 新文件唯一入库口。ReserveMeta 原子占位 → uuid 派生物理路径 → `.partial` 排他写+Sync+硬链接发布 → CompleteIntake 确认。5MB 上限（= describer.MaxFullBytes）；同逻辑键（含软删/幽灵/占位）拒绝；描述/落库/喂索引归编排机事件流 |
| modify | Modify / ModifyByUUID | 追加/覆盖，原子替换（平台分文件）；软删/幽灵/未发布拒绝 |
| move | Move / MoveByUUID | 逻辑键改 + 谱系边（MoveMeta 同事务）；扩展名改变 → 物理改名 + 持久化待恢复记录 |
| placement | StoragePathOf / StorageAbs / Resolve | 物理布局 `<uuid前2位>/<uuid><ext>`（盘面随机不可猜）；Resolve = Locate 纯路径薄壳；validLogicPath 防穿越/盘符（common.ResolveWithin） |
| fetch | Locate / LocateMany / Open / Read（+ ByLogic 系列） | uuid 兑换处。**Locate 知情性质**：软删照报（IsDeleted=true），不查盘；**Open/Read 动手性质**：软删 ErrDeleted、盘无 ErrGhost；流不设预算（产品决策归调用方）；LocateMany 缺失不入 map（免 N+1）；Read = Open + 限读 |
| buffer | （fetch 内部）/ BufferStats | LRU 64MB / 单条目 5MB；put 快照复制 + get 时 stat 新鲜度对拍（mtime/size 漂 → 失效重读）；大文件旁路直流；**不服务下载**（只服务 agent 反复读小文件）；纯派生态可丢可清 |
| download | IssueDownloadURL / VerifyDownloadTicket | 短期签名下载地址唯一产出方；单文件绑定 + 过期；无状态签验对称；装配层 handler 只验签不出链接 |
| updater | AnalyzeFile（T3）/ Backfill（T2 一轮） | 执行器唯一路径：stat → head 512B + 惰性全量 + 流式 checksum → describer.Analyze → runMetaUpdate 临界区（GetMeta → MergeResults → UpsertMeta → sink.Update）。stale 快慢两段（零 IO 三条件先行，checksum 慢路径兜底）；连续 3 轮盘上缺失 → SoftDeleteMeta + 索引卸载；curVer 来自 describer.CurrentVersions()；一轮结束即返回，绝不自旋 |
| audit | Audit | 盘 vs DB 对账：孤儿文件/幽灵元数据/重复 checksum → AuditReport；含软删游标分页；**只报告不动手** |
| cleanup | PlanCleanup / ApplyCleanup | 显式清理计划（身份/发布状态/冲突校验），按天归档已完成发布的临时目录项；执行持 intake 写锁等待在途发布 |
| directories | CreateDirectory / CreateChildDirectory / WriteInDirectory(Request) / ImportInDirectory / CopyInDirectory / ListDirectory / LocateDirectory / DirectoryAt | UUID 目录项：显示名独立于逻辑键，**允许同名文件**；逻辑空目录持久化（物理 dataDir 不建目录）；requestID 幂等重放 |
| directory_export / import | ExportDirectory / ImportDirectory | ZIP 导出带逐项授权回调 + UUID 清单；本地目录递归导入逐项结果 |
| tree | LogicTree / LogicPaths | 元数据 + 逻辑空目录 → 逻辑树（目录在前按名排序，不含软删） |
| lineage | Related | 文件关系边（copied_from / moved_from）；lineage 表为将来扩展 |

### 3.4 文件生命周期与崩溃恢复

```
写入：ReserveMeta 占位(产 uuid) → .partial 排他写 + Sync → 硬链接发布正式路径 → CompleteIntake 确认
      发布前失败 → 归档占位释放名称；发布后确认失败 → 保留 pending 供启动恢复
移动（改扩展名）：持久化待恢复记录 → 物理改名 → 确认；中断由恢复流程排他发布目标
启动顺序（doc.go 钉死）：RecoverPendingMoves → RecoverPendingIntakes → 再接收请求 / 启动扫描
删除：软删（SoftDeleteMeta）保留描述与谱系；连续 3 轮盘上缺失由 T2 自动软删幽灵
```

### 3.5 并发模型

- `intake sync.RWMutex`：入库持读锁（可并发）；清理执行持写锁等待在途发布。
- `mutation sync.Mutex`：单实例内修改与移动串行。
- `metaUpdate` 钩子：T2/T3 逐文件 DB 读-改-写与索引发布纳入编排机同一临界区（单写者模型，
  见 `管理机与索引机更新机制.md`）。
- 首次使用后不可复制；**不提供跨实例事务保证**（单实例部署口径）。

### 3.6 铁律（架构设计.md 第 4 节）

1. DB 交互归 repo——manager 编排 Store，不写 SQL；describer 保持纯库不碰 DB。
2. 自动只巡检报告，动手必须显式——路径是 agent 的组织语言 + 元数据唯一键，后台自动归档会破坏路径预期。
3. 编排循环发生在时间轮次（timer/启动驱动），一轮 = 查→处理→写→结束，绝不自旋、无递归栈累积。
