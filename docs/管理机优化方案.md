# 管理机优化方案

> 2026-10-08。后续管理机开发按本方案推进，分批实现和验证，优先保持简单、可维护。

## 1. 核心分工

- **索引机负责查找**：名称、目录、标签、描述等条件 → UUID 集合。多个候选由调用方选择，管理机不猜测。
- **管理机负责存取与操作**：外部服务通过 UUID 与管理机交换文件、目录身份；名称与路径只是组织和展示信息。
- **装配层负责授权与编排**：执行操作前检查当前权限；UUID 不是授权凭证。持久化与查询由 repo 实现。
- 新建尚无 UUID：提交内容、名称、父目录 UUID，管理机分配并返回新 UUID。根目录也有稳定 UUID。

## 2. 统一交互规则

| 操作 | 管理机输入 | 输出 |
|---|---|---|
| 新建文件 | 父目录 UUID、名称、内容 | 新文件 UUID、保存结果 |
| 取文件/修改文件/改名 | 文件 UUID及相应参数 | 文件回执 |
| 移动 | 文件或目录 UUID、目标目录 UUID | 操作回执 |
| 复制 | 来源 UUID、目标目录 UUID、名称 | 新对象 UUID |
| 创建目录 | 父目录 UUID、名称 | 新目录 UUID |
| 列出/导出目录 | 目录 UUID | 子项 UUID清单/归档结果 |

现有路径入口作为过渡适配：先解析为 UUID，再执行 UUID 操作；新入口以 UUID 为准。
身份与关联不依赖可变路径，短链和谱系逐步绑定 UUID。

## 3. 重名规则

- 同名文件是不同对象，每份有独立 UUID；读取指定 UUID，绝不按名称默认选最新。
- 名称允许重复是目标规则，但当前 `file_path` 唯一约束尚不支持；需先适配存储与旧路径入口。
- 路径解析遇到多个可见候选返回明确歧义，不静默选一份；查找与选择交给索引/调用方。
- 自动加 `(2)` 仅作为可选展示或导出冲突策略，不承担身份识别。
- 同一次上传重试应复用请求 ID，主动再次上传用新请求 ID；不能用文件名或 checksum 推断用户意图。

## 4. 可靠性：最小必要实现

- 保留轻量入库状态记录，占位与状态创建在同一数据库事务中完成。
- 新内容先写临时文件，确认完整、关闭并完成必要同步后才发布正式文件；读取不暴露半文件。
- 启动只执行一轮未完成操作恢复，支持重复执行；不能仅凭普通文件存在认定完成。
- 已落盘但状态确认失败时保留内容供恢复，不误报成功、不自动另建副本。
- 失败补偿只作用于本次 UUID，保留失败内容与记录；不按“缺文件”猜测并处理历史文件。
- 当前阶段按单服务进程设计；恢复必须先于接收请求与后台扫描。多实例恢复暂不承诺。
- 修改旧文件的原子更新独立验证；不将新建恢复的保证套用到覆盖修改。

## 5. 文件夹兼容：近期重点

- 文件夹拥有 UUID、父目录 UUID、名称；支持空目录，逻辑目录与物理文件位置分离。
- 先落地创建、列出、目录内文件新建与读取；兼容现有数据和路径 API。
- 再增加目录移动与复制：禁止移入自身或后代，明确并发规则。
- 存文件夹：遍历相对路径，复用单文件入库，返回逐项 UUID与错误；可继续未完成项。
- 取文件夹：按目录 UUID取得清单，逐文件读取，使用 Go 标准库生成 ZIP，保留空目录。
- 名称重复导出到普通文件系统/ZIP时必须生成无冲突路径，并附 UUID到导出路径的映射清单。
- 不增加复杂 ACL 继承、完整版本库、通用任务平台或额外存储服务。

## 6. 实施顺序与验收

1. 核对并修正现有轻量恢复的完整性判定、启动顺序；整理重复状态迁移声明。
2. 给目录增加 UUID，接通 UUID 文件/目录操作入口，保留旧路径兼容。
3. 适配重名存储：评估并迁移路径唯一约束，保证旧布局文件仍能按 UUID取回。
4. 实现文件夹导入和 ZIP导出，再补目录移动/复制。

每批只修改所需接口，增加有意义的边界测试并运行相关 Go 模块回归。
重点验收：同名不同 UUID不串件、改名/移动后 UUID仍可取、空目录往返、权限变化、
重试不重复保存、部分写入不发布、启动恢复幂等、旧数据可读、重复名称导出不丢文件。

## 7. 当前状态

UUID 操作修正（2026-10-08）：新增 MoveByUUID（文件 UUID、目标目录 UUID、显示名称），
目标使用不透明逻辑键以支持同名文件；存储事务按 UUID 锁定源行，同步目录关联与移动恢复记录。
move_file 接受 file_uuid / directory_uuid / name，检查管理机接线、源 UUID 写权限及目标目录归属，旧路径参数继续兼容。
move_operations 保留单一定义，新增列通过 ALTER IF NOT EXISTS 兼容已有数据库；pending 移动不进入目录清单。
CopyInDirectory 在管理机层提供 UUID 复制，限制为当前 5 MiB 内容预算；占位、目录关联、私密归属及 copied_from 同事务写入，随后复用新建发布与恢复。
copied_from 仍保存源逻辑路径以兼容既有谱系查询；复制尚未接通 MCP/HTTP，亦不复制来源的全部描述属性。
Go 回归与 PostgreSQL 临时表验证通过，覆盖同名 UUID 不串件、移动 pending 隐藏及无效复制来源事务回滚。

进一步一致性修复（2026-10-08）：修改使用独立暂存内容，Sync/Close 后同目录替换，
不再截断正式文件，丢失内容返回 ErrGhost；UUID 修改不再二次按路径定位。
同一 Manager 的修改、移动和打开内容阶段串行，写后主动失效缓存；不承诺多实例并发 CAS。
UUID/路径取件和重分析拒绝 reserved，批量取件与普通分页隐藏 reserved，审计仍包含占位。
文件存在时独立清零 missing_rounds，不依赖重分析额度或陈旧判定。
目录重分析使用显示名称推导 MIME/扩展名，存储键保持不变；上层 T1 描述入口仍需独立核对。
Windows 使用 MoveFileExW 替换，其他平台使用同目录 rename；断电耐久性尚未验证。
失败修改暂存文件保留供对账，改扩展名 Move 的跨数据库/文件系统中断恢复仍待实现。

可靠性补丁（2026-10-08）：正式 PostgreSQL目录入库把 UUID占位、目录关联、显示名称和
私密归属放入同一事务，发生在物理写入之前；reserved记录不进入目录清单。
旧路径 Move同步现有目录关联与stored操作路径；若目标还没有显式目录则按当前路径复判列表。
保留的.partial仅在属于已知UUID物理位置时不作为孤儿报告，未知partial仍报告。
目录文本写入支持可选request_id，重复参数读回原UUID，参数不同拒绝；限制为未移动/修改/删除的对象，
文件夹批次和二进制导入尚无幂等。无request_id仍可主动创建同名副本。
真实PostgreSQL临时表测试覆盖原子归属/关联、reserved隐藏与移动联动；不是完整HTTP/MCP验收。
仍需处理并发修改CAS、复制关联、描述事件丢失恢复、ZIP内容变化、备份及容量保留策略。

实施记录（2026-10-08）：目录表已增加 UUID；`directory_files` 将显示名称、父目录 UUID
与文件 UUID 关联，同名目录文件无需移除旧 file_path 唯一约束。旧路径文件仍可列出和取回。
新增 MCP `list_directory` / `create_child_directory` / `write_directory_file`，`read_file` 接受 UUID。
新增 HTTP `GET /api/directories/{uuid}`、`GET /api/directories/{uuid}/zip`、
管理员 `POST /api/directories/{uuid}/import`（受信本地来源）。
目录导入逐项回执，ZIP保留空目录，同名项使用 UUID后缀并带映射清单。
新建和导入先同步写入 .partial，再排他硬链接发布正式内容；不支持硬链接则返回明确失败。
成功/失败临时文件保留，须后续独立归档；这是单进程、本地文件系统恢复保证，尚未验证断电持久性。
启动恢复先于索引重建和事件消费。文件已落盘但目录关联失败会返回文件 UUID供定位，不声称整体成功。
仍待：上传请求幂等、目录移动/复制、所有旧操作入口 UUID化、浏览器目录上传控件与空目录权限展示。

已有 UUID取件接口；部分 MCP/HTTP和写操作仍按路径；目录仍以路径存储。
工作区中的轻量恢复、空目录与重名保护尚未收尾，不能视为已完成 UUID统一交互。
本方案优先于此前文档中的默认自动改名及复杂目录设计建议；本次只记录方案，不执行迁移。
