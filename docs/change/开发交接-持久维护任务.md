## 一、 本轮已完成工作总览

### 1. 持久维护任务闭环与管理机 T2/T3 逐文件串行锁（已提交：`b72bcac`）

* **解决悬空 `prepared` 任务问题**：
  * `mcp-server-go/core/orchestrator.go`：`core.Event` 新增 `UUID` 与 `MaintenanceJobID`。
  * 各写入/复制/导入入口（`write_file`、`upload_file`、`copy_file`、`jm_comic`、`write_directory_file`、HTTP 目录导入/复制）在管理机落盘后调用 `PrepareMaintenance`，并将返回的 `jobID` 随 `core.Event` 提交给 `orch.Submit`。
  * **状态机闭环**：worker 执行 `execute` 成功后调用 `FinishMaintenance(jobID, "done", "")`；执行失败置 `retry`（交由 `RetryMaintenance` 退避重试）；若 `Submit` 因队列满或关停被丢弃，立即调用 `FinishMaintenance(jobID, "ready", reason)`，无需等进程重启即可被周期 `RetryMaintenance` 消费。
* **解决管理机 T2 (`Backfill`) / T3 (`AnalyzeFile`) 锁外写 DB 与重入死锁问题**：
  * `manager-go/manager.go` & `updater.go`：新增 `SetMetaUpdateRunner(func(fn func() error) error)`，将逐文件的 `GetMeta -> MergeResults -> UpsertMeta -> sink.Update` 以及幽灵 3 轮软删 `SoftDeleteMeta -> sink.Update` 包裹在同一临界区内，文件 IO 与哈希计算保持在锁外。
  * `mcp-server-go/core/maintenance.go`：新增 `orch.BindManager(mgr)` 注入 `updateMu` 锁，配套 `orch.ManagerIndexSinkBound()`（`locked: true` 避免 `Update` 回调重入死锁），并提供 `orch.AnalyzeFile` / `orch.Backfill` 编排门面。
  * `mcp-server-go/cmd/server/main.go`、`internal/api/analyze.go`、`internal/tools/analyzefile/analyzefile.go`：全部切换至编排机门面；启动阶段 `mgr.RecoverPendingMoveOps` 恢复未完成移动后立即为其生成 `ready` 维护任务，在启动 `RetryMaintenance` 中重分析新文件名属性。

### 2. 图片/二进制上传能力与 MCP 工具边界引导（当前工作区改动）

* **图片与二进制上传闭环**：
  * `manager-go/intake.go`：新增 `WriteBytes(ctx, logicPath, data []byte)`，与 `Write` 共享 5MB 上限、重名拒绝与 `.partial` 硬链接原子发布。
  * `mcp-server-go/internal/tools/writefile/writefile.go`：同包注册 **`upload_file`** MCP 工具，支持 `content_base64`（兼容纯 Base64 与 `data:image/...;base64,...` Data URL）或宿主机 `source_path`（限管理员/Master Key），支持内联传 `title`、`description`、`tags`、`visibility`、`attributes`（`llm-*` / `sp-llm-*`）。上传后自动触发描述机提取 `cod-image-*` 视觉量化特征并挂入内存索引，返回 24 小时分享短链。
  * `mcp-server-go/core/executor.go`：`mergeSourceAttributes` 支持在写/上传事件中将内联传入的 `llm-*` / `sp-llm-*` 属性经 `llm.OpenLLM()` 校验后一并落库（自动拦截篡改 `cod-*` 的输入）。
  * `mcp-server-go/internal/api/files.go` & `router.go`：新增 `POST /api/files/upload`（支持 `multipart/form-data` 与 JSON `content_base64`）。
* **MCP 协议级引导与工具边界明确化**：
  * `mcp-server-go/internal/mcp/server.go`：在 `NewMCPServer` 中注入 `server.WithInstructions(serverInstructions)`，客户端连接握手即获知五大类工具职责边界（新建文本 vs 上传图片、局部 `patch_file` vs 整篇 `modify_file`、`describe_file` 写 `llm-*` vs `analyze_file` 算 `cod-*`、两步检索 `list_index_fields` → `search_files`）。
  * `mcp-server-go/internal/mcp/resources.go` & `prompts.go`：新增 `mabel://guide/workflow` 资源（工具边界速查表 + 图片上传 SOP）与 `upload_and_manage_media` Prompt 模版。
  * 各 MCP 工具 Description 统一补充 `[BOUNDARY]` 边界说明。
