# 权限设计（认证 + 授权 + 归属）

> 状态：批次①②已实现（2026-09-06）——认证底座、授权单点、归属打标、MCP 双轨 key、
> 前端鉴权四件。批次③（组管理 UI 与 game/ 联动）与批次④（admin 面板 UI）待做。
> 实现载体：`mcp-server-go/internal/authz/`（策略单点）+ repo 迁移 + api/mcp/tools 三侧接线。

## 1. 信任模型（三个 actor）

| 主体 | 凭证 | 来源 | 权限 |
|---|---|---|---|
| 普通用户 | JWT | 开放注册（role=user） | 矩阵内 |
| admin | JWT | users.role=admin（bootstrap 自建/自提升） | 全权 |
| 管家 agent | master key | `.env MCP_API_KEY`（不入库） | **无限**（含 execute_command） |
| 外部 agent | 受限 key | agent_keys 表（admin 签发，**绑定一个用户**） | =绑定用户，无 shell |

- MCP 做**通道级**信任：是"我的 agent 吗"。外部 key = 某用户的代理凭证，
  策略完全复用用户格子——群友经 agent 间接操作，agent 对终端用户负责。
- HTTP 与 MCP 经同一 `authz.Principal` 判权，`context` 贯通
  （mcp-go 的 message ctx 基于 r.Context() 构建，中间件注入直达工具层）。

## 2. 主体 × 资源 × 操作矩阵（authz.go 是唯一实现）

资源三档可见性：`public`（全局）/ `group`（组内）/ `private`（个人）

| 主体＼操作 | 读 public | 读 group | 读 private | 写 public | 写 group | 写 private | execute_command | admin 面 |
|---|---|---|---|---|---|---|---|---|
| 用户 | ✅ | 本组 | 自己 | ❌ 只读共享 | 本组协作 | 自己 | ❌ | ❌ |
| admin | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ❌ | ✅ |
| 管家 | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| 外部 agent | =绑定用户 | =绑定用户 | =绑定用户 | =绑定用户 | =绑定用户 | =绑定用户 | ❌ | ❌ |

**存量口径**：`owner_id IS NULL` 的老文件视为"无主遗产"——迁移给
`visibility='public'`（人人可读），写权归 admin/管家。**新文件默认 private**。
无元数据行的新盘上文件按 public 可读（与 CanRead 空 ACL 一致，三处端点同口径）。

**copy 语义**：副本归操作者（拿走即拥有），`copied_from` 保留谱系，可见性继承源。

## 3. 数据模型（repo 迁移，2026-09-06）

```
users          + role TEXT NOT NULL DEFAULT 'user'        （bootstrap admin 自提升）
file_metadata  + visibility TEXT NOT NULL DEFAULT 'public' + group_id BIGINT
                 （owner_id 列既有，开始真写）
groups(id, uuid, name UNIQUE)  +  group_members(group_id, user_id) PK
agent_keys(id, name, key_hash UNIQUE, principal_uid→users, is_active)
                 ——raw key 只在签发响应出现一次，库存 sha256
```

检索（SearchFiles）带观察者过滤：非 admin 自动附加
`visibility='public' OR owner_id=$viewer OR (visibility='group' AND group_id=ANY($groups))`。

## 4. 执行点分层

```
认证（你是谁）                    授权（你能动谁）                归属（记谁头上）
─────────────                    ──────────────                ─────────────
HTTP requireAuth                 api 层 canActFile/denyLog      core.Event.Actor
  → 查库实时 is_active/role/组     MCP 工具层 CanFile/Deny        → 执行器落 owner_id
MCP AuthMiddleware               （判定单点 = authz 包）          （仅 KindWrite / 首描述）
  master key / agent_keys 查库
```

- **判定与记录分离**：授权判定在入口层（api/tools），归属记录在编排机执行器
- 授权拒绝一律留痕（WARN：op/path/user/ip/reason——安全审计第一现场）
- key 验证失败、限流命中、封号登录、admin 启停用户/签发吊销 key 均留痕

## 5. 端点面（HTTP）

- 公共：`/health`、`auth/login`（限流 5/分/IP）、`auth/register`（限流 3/时/IP，
  用户名白名单 + 密码≥8，role=user，注册即发 token）、`auth/refresh`（角色实时重签）、
  `auth/logout`、`files/download`（自证：静态 access_token 过渡口径 **或** JWT+CanRead）
- JWT：files 列表（目录树按可见性裁剪）/ search（观察者过滤）/ metadata 读写 /
  copy / analyze / download-zip（逐路径过滤）/ operations / commands
- **admin**：`files/backfill`、`admin/users`（列表/启停）、`admin/groups`（增删/成员）、
  `admin/agent-keys`（签发——raw 只回一次/列表脱敏/吊销）

## 6. 配置与开发口径

- `api.require_auth` 默认 **true**（安全默认）；本地裸奔设 `REQUIRE_AUTH=false`
- `mcp.api_key`（MCP_API_KEY）空 = **开发放行** + 启动大红 WARN（管家主体注入）；
  生产必配强随机——key 即管家全权（含 shell）
- MCP 工具参数新增：`write_file.visibility`（默认 private）、`describe_file.visibility`

## 9. 已知取舍

- **requireAuth 每请求查库**（is_active+role+组）——换实时封号，个人库量级主键查无压力
- **execute_command 仅管家**——外部 key 泄露也不交出 shell 权
- **下载双轨**：JWT（前端 blob）+ 静态 access_token（agent 直发链接的过渡口径）；
  将来由管理机 download 票据域（短期签名 URL）取代
- **public 文件对普通用户只读**——共享不互踩；组内可写是协作档
