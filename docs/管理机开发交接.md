## 1. 定位与三铁律

**管理机 = 文件位置与谱系的唯一知情者**。其他组件不摸文件系统、不查谱系表——路径与关系问题只有它回答。它是编排层，不是数据层。

三铁律（`manager-go/manager.go` 包注释，违反即架构事故）：

1. **DB 交互归 repo**——manager 编排 repo（调用），不拥有（不写 SQL）
2. **自动只巡检报告，动手必须显式**（`move_file`）——路径是 agent 的组织语言 + 元数据唯一键，后台自动归档会破坏 agent 路径预期
3. **编排循环发生在时间轮次**（timer/启动驱动），不发生在调用栈里——一轮 = 查→处理→写→结束，绝不自旋，无递归无栈累积

## 3. 模块拓扑与接线

```
HTTP / MCP 工具层（mcp-server-go，装配层）
        │ require + replace
        ▼
manager-go ──require──▶ describer-go（updater 用引擎）
     │            ────▶ indexer-go（updater 喂食）
     ▼
Store 接口（依赖倒置，本包定义；repo 实现满足签名后由装配层注入）
```

- **manager 不 import mcp-server-go**（反向依赖成环）；不 import 兄弟模块中的装配层代码
- 接线方式：`mcp-server-go/go.mod` 加 `replace github.com/Reisentyann/Mabel-s-Tentacles/manager-go => ../manager-go`；**Docker 构建上下文必须已是仓库根**（现状如此，describer/indexer 同款），否则镜像拿不到同级模块
- 依赖方向铁律：`HTTP/MCP → manager → repo + describer + indexer`，uuid 是组件间货币

## 4. 依赖面详解（你需要的全部外部信息）

### 4.1 describer-go 引擎面（T2/T3 执行器唯一路径）

执行器五步（幂等，可中断续跑）：**读文件 → `Analyze` → `MergeResults` → `Upsert` → 喂食索引机**

| 符号 | 签名要点 | 用途 |
|---|---|---|
| `describer.Analyze` | `Analyze(in Input, load Loader) []Result` | 全插件流水线；`Input{Path, Head, Full, Size, MTime, ExtMime}` |
| `describer.Loader` | `func() ([]byte, error)` | T3 读盘时惰性传；**预算截断（512B 头 / 5MB 全量）由引擎内部强制**（2026-09-04 下沉），你不用截 |
| `describer.MergeResults` | `(existing map[string]any, results []Result, now time.Time) map[string]any` | cod 轨整族合并，保留 llm-*/sp-*；读-改-写由你负责持久化 |
| `describer.IsStale` | `(attrs map[string]any, family string, curVer int, storedChecksum, curChecksum string, mtime time.Time) bool` | T2 陈旧过滤（四条件：缺 ver / ver 落后 / checksum 漂 / mtime 新） |
| `describer.AttrsFromJSON` / `JSONFromAttrs` | attributes JSON ↔ map | 落库前后的转换 |

**注意**：`MergeResults` 需要读旧 attributes（`GetMetadata` 取 `Attributes` 后 `AttrsFromJSON`）。T1 现成参考实现在 `mcp-server-go/internal/tools/common.go` 的 `RecordFileMeta`（head 512B + 全量 + 合并 + Upsert + 日志五要素）。

### 4.2 indexer-go 喂食面

| 符号 | 用途 |
|---|---|
| `indexer.Indexer` 接口：`Query(conds, mode) ([]string, error)` | 条件 → uuid 集合（纯查询） |
| `Update(uuid string, old, new map[string]any)` | **写路径喂食**：old/new 为 Upsert 前后的 attributes（读-改-写时各取一份），实现逐字段 diff；幂等；new 为 nil = 整体移除 |
| `Rebuild(all map[string]map[string]any) error` | 启动时全量重建（uuid → attributes） |
| `Stats() Stats{Fields,Keys,Mounts}` | 自省计量（排障用，2026-09-04 新增） |

喂食点约定：**T2 回填、T3 重分析、describe_file 之后**，Upsert 完成由编排方调 `Update` 做 diff 增量。execute_command 直改文件的绕口由 IsStale 条件 3（checksum 漂移）对账兜底，最终一致。

### 4.3 repo 现有方法与适配面

repo（`mcp-server-go/internal/repo/repo.go` 的 `Store`）现有可直接适配的：

- `UpsertMetadata(ctx, *FileMetadata)` / `GetMetadata(ctx, filePath)` / `GetMetadataByPaths`
- `SoftDeleteMetadata(ctx, filePath)`（**闲置中，等你接**） / `IncrementDownloadCount`（download 域用）
- `CopyMetadata(source, target, sessionID, userID)`（现状 copy_file 用，Move 的谱系边参考它的语义）

**需要 repo 侧新增的**（manager.Store 钉面时提出，repo 写适配器）：

- `GetMetadataByUUID(ctx, uuid)` —— Resolve/Related 的支撑（uuid 是组件货币，现有接口只有按 path）
- 分页/全量列元数据（T2 扫描与 audit 需要，如 `ListMetadataPage(ctx, sincePath, limit)`）
- 幽灵"连续缺失轮次"存续状态（audit 域需要，新列或独立小表）
- 按 checksum 分组查询（重复检测）

**DTO 归属**：manager 定义自己的 DTO/基本类型（不 import repo 的 `FileMetadata`），repo 侧写适配——这是"依赖倒置，io.Reader 模式"的具体含义。file_metadata 表结构见 `repo.go` migrations（uuid 列默认 `gen_random_uuid()`，Upsert 不动它）。

### 4.4 文件系统操作（内化，不 import）

防穿越校验、读文件、盘上枚举的现成纯函数在 `mcp-server-go/internal/service/files.go`（`ResolvePath` / `SafeRead` / `SafeList`）——**语义参考，逻辑内化进 manager**（manager 不能反向 import mcp-server-go）。Manager 需要持有 `dataDir string`（骨架 TODO 已列）。

### 4.5 配置

T2 回填开关：`describe.backfill: {enabled, batch, interval}`，**默认关闭**（字段字典 10.3）。配置解析归装配层，manager 收参数。

## 5. 五域实现要点（建议顺序：updater → placement → audit → download → lineage）

### updater（价值最高，T2/T3）
- T3 `AnalyzeFile`：ResolvePath → SafeRead → `Analyze`（Loader 惰性传全文）→ 读旧 attrs → `MergeResults` → `Upsert` → `idx.Update(uuid, old, new)`
- T2 `Backfill`：分页扫元数据 → `IsStale` 过滤（先 stat 比 mtime，再决定要不要算 checksum——快路径）→ 逐个 AnalyzeFile → 返回计数。由装配层 goroutine 按 interval 驱动，一轮结束即返回
- 盘上文件消失：跳过 + WARN；**连续 3 轮缺失 → `SoftDeleteMetadata`**（对接软删除待办）
- 超 5MB：引擎只给 basic 家族事实（截断内部处理，无需特判）；解码失败静默降级（插件行为）
- MCP `analyze_file` 工具与 HTTP `POST /api/files/analyze`、`POST /api/files/backfill` 在装配层加，调这两个方法

### placement
- `Resolve`：uuid → file_path（repo 补 GetMetadataByUUID）
- `Move`：防穿越校验 → 物理改名 → 元数据唯一键迁移（file_path 换键）→ 谱系边（moved，见 lineage）→ **不动索引**（attributes 未变，索引按 uuid 挂载与 path 无关）
- 对应 MCP `move_file` 工具（装配层注册）

### audit
- 盘上全集（SafeList 语义内化）vs DB 元数据全集 → 三类差异：孤儿（盘有 DB 无）/ 幽灵（DB 有盘无，带连续缺失计数）/ 重复 checksum
- **只产报告，不动手**（铁律 2）。幽灵计数喂给 updater 的 3 轮 SoftDelete 判定

### download
- `IssueTicket`：`hmac(secret, path+exp)` → 短期 URL（`/api/files/dl?file=&exp=&sig=`，ttl 建议 10 分钟）
- `VerifyTicket`：对称验签纯函数，handler 唯一调用点，handler 不再拼链接
- `download_count` 计数归本域（repo.IncrementDownloadCount 已有）；静态 ACCESS_TOKEN 降级为"申请票据资格"

### lineage
- 现成边：`file_metadata.copied_from`（copy_file 产物）+ operations 表（命令执行记录）
- 将来：lineage 表成 DAG（`Relation.Kind`: copied / moved / derived）
- `Related`：先查 copied_from + lineage 表，返回邻居

## 6. 已知缺口与设计提醒（读后少踩坑）

1. ~~**`IsStale` 的 curVer 来源缺口**~~ **已解决（2026-09-05）**：describer-go 根包导出 `CurrentVersions() map[string]int`（遍历 registry，basic 只认首个注册），updater 已在用，无需硬编码常量表。
2. **Move 不喂索引**：uuid 是索引键，path 变更不影响桶内挂载。骨架注释里"喂食索引机 Update"针对的是重分析场景，Move 场景下 attributes 不变则无 diff。
3. ~~**T1 写路径的索引喂食属装配层**~~ **钩子已预埋（2026-09-05）**：`RecordFileMeta` 签名改为收 `tools.Deps`（含 `Sink manager.IndexSink`），Upsert 后 diff 喂食调用点就位；装配层注入 indexer 实例即点亮（索引机批次，含启动 Rebuild 与 describe_file 喂食）。
4. ~~**幽灵计数存续**~~ **已解决（2026-09-05）**：`file_metadata.missing_rounds` 列（INT NOT NULL DEFAULT 0），`MarkMissingRound` 递增、Upsert 清零（写入即存在证据），3 轮软删已接 `SoftDeleteMetadata`。
5. **uuid 生成归 DB**（`gen_random_uuid()` 默认值），manager 不自己生成 uuid，只读和传递。**`UpsertMetadata` 已返回 uuid**（RETURNING），组件货币有了出库口。
6. **日志五要素**（出 bug 唯一证词）：入口 / `session`·`user` / 操作现场（path 等） / `duration` / 结果（失败必带 `error`，成功带产出计量如 `analyzed`、`moved`）——权威定义 `mcp-server-go/internal/logging/logging.go` 包注释。
