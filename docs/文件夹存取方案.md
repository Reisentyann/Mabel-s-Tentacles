## 结论与依据

建议采用 PostgreSQL 中的显式目录项树，文件内容继续由管理机持有。
目录项使用稳定 ID、parent_id、name、kind、owner；文件项关联已有文件 UUID。
不引入分布式文件系统服务。目录结构与物理内容分离，空目录有实体记录。

查阅的一手资料：

1. Linux VFS Pathname lookup：https://www.kernel.org/doc/html/latest/filesystems/path-lookup.html
   dentry 将名称、父目录和 inode 联系起来；借鉴名称与内容身份分离，不照搬内核缓存/锁实现。
2. Amazon S3 prefixes：https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-prefixes.html
   官方明确 prefix 并非目录。当前 LogicTree 的路径拼树类似这一模型，适合浏览，不足以单独表达空目录和稳定目录身份。
3. PostgreSQL recursive queries：https://www.postgresql.org/docs/16/queries-with.html
   邻接表用递归 CTE 查询子树，并可检测环。检测环不能替代并发移动的事务锁。
4. SQLite Atomic Commit：https://www.sqlite.org/atomiccommit.html
   借鉴日志、提交点、flush 和恢复机制；不建议替换项目的 PostgreSQL。
5. OSDI 2014，Pillai 等，All File Systems Are Not Created Equal:
   https://www.usenix.org/conference/osdi14/technical-sessions/presentation/pillai
   本次阅读会议摘要：应用崩溃一致性依赖底层持久化语义，不能仅凭 rename 就宣称跨平台断电安全。

## 数据结构与兼容

拟新增 namespace_entries 表（新表理由：空目录、统一文件/目录名称冲突、稳定目录 ID）。
字段：id、owner_id、parent_id、name、kind(file/dir)、file_uuid、is_deleted。
同一 parent_id 下 name 唯一；每个用户有显式根节点，根节点使用单独唯一约束。
父节点必须是目录，文件/目录共用名称空间；约束与事务检查共同保证。

第一阶段保留 file_metadata.file_path 及现有路径 API；目录移动在同一 DB 事务中
更新所有后代的逻辑路径。此阶段移动不是 O(1)，但无需搬文件内容。
后续路径逐步转为派生视图后才可只更新父节点。复制谱系目前按路径存储，须一并评估迁移到 UUID。
元数据中的 owner/权限语义保持显式，第一版不增加复杂 ACL 继承。
并发目录移动先采用每用户事务级 advisory lock；事务内验证后代关系和名称冲突。

物理布局目前依赖 UUID+逻辑扩展名：新增独立 storage_key 前，保持原派生规则，
不允许目录迁移顺便改变文件扩展名。改为稳定 storage_key 时保留旧布局读取兼容，逐项校验迁移。

## 接口与批量流程

- CreateDirectory / ListDirectory（分页）/ MoveDirectory：先完成空目录和基本组织。
- ImportDirectory：创建持久化批次与相对路径清单，逐文件存入、记录 UUID/checksum/错误。
  已完成项重试复用；默认整个根目录冲突拒绝，自动改名作为明确策略，不静默合并覆盖。
- ExportDirectory：固定目录清单；逐文件权限检查，准备 ZIP，检查全部条目与关闭错误后发布下载链接。
  使用 Go archive/zip 流式读写磁盘，保留空目录与相对路径，不将整目录读入内存。
  固定清单不等于内容快照：第一版发现修改即失败重试；真正快照需不可变内容版本。
- 路径规范拒绝绝对路径、..、符号链接及平台名称冲突；导入来源限定受控上传区。
- 不允许缺文件的包被标记 completed；批次分别返回完成、失败、未处理计数。

拟新增 transfer_jobs / transfer_items（理由：断点、幂等、重启恢复不可只放内存）。
状态 planned → receiving → verifying → ready，异常为 failed；重试复用 job_id。
多文件跨磁盘和数据库不能由一个 SQL 事务保证原子：逐项确认内容持久化后，在短事务发布清单。
