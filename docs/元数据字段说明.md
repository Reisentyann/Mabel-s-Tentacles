# 元数据字段说明（`file_metadata.attributes` 约定）

> 本文档是 attributes 字段的**唯一权威定义**。新增/修改字段必须先改这里再写代码；
> 实现位于仓库根 `describer-go/`（与 `mcp-server-go` 同级的独立 Go 模块），
> 其插件注册表与本文件一一对应，实现完成后可由注册表自动生成本文档。

---

## 1. 命名法则（前缀即权限）

| | 固定字段（封闭集，逐个定义） | 自由字段（文件特有，任意增删） |
|---|---|---|
| 代码产出（确定性、可复现） | `cod-<插件>-<字段>` | `sp-cod-<字段>` |
| 模型产出（概率性、语义解释） | `llm-<字段>` | `sp-llm-<字段>` |

**强制规则**（由前缀闸门执行，不是君子协定）：

1. 硬编码描述器只允许产出 `cod-` 固定字段——字段在 Facts 结构体中强类型声明，未声明的字段**编译不过**；
   确定性代码永远不写任何 `llm-`、语义类字段。
2. 模型轨（服务端 Ollama 与 agent 直接调用 `describe_file` 都算）提交的字段过解析器闸门：
   `llm-` 后必须命中第 5 节的受控词表，`sp-llm-` 任意放行，**其余前缀一律丢弃并记 WARN**。
3. `sp-` 自由字段挂各自来源前缀（`sp-cod-` / `sp-llm-`），永远不裸奔。
4. 语义层（模糊类型、图中内容、文风）**只属于 `llm-`**；结构层（行数、色板、标题行）**只属于 `cod-`**。

## 2. 顶层列与 attributes 的分界（不双写清单）

以下信息已是 `file_metadata` 顶层列，**禁止**再写进 attributes：

| 顶层列 | 内容 | 与 attributes 的关系 |
|---|---|---|
| `file_path` | 文件相对路径（含文件名） | 文件名不另存 |
| `size_bytes` | 文件字节数 | "文件大小"不另存 |
| `checksum` | SHA-256 | |
| `extension` | 扩展名（含点小写） | |
| `file_type` / `mime_type` | **扩展名推断**的粗类型/MIME | 与 `cod-basic-mime`（字节嗅探）分工见下 |
| `title` / `description` / `tags` | 描述三件套 | 追加模式作用于 `description` 列 |
| `scope` / `session_id` / `user_id` / `copied_from` | 归属与溯源 | |
| `created_at` / `updated_at` | **元数据行**的数据库时间 | 文件系统时间另见 `cod-basic-mtime` |

> `mime_type` 列 = 扩展名推断；`cod-basic-mime` = 魔数嗅探。两者可能不一致，
> 一致性由 `cod-basic-mime-match` 记录（扩展名伪造检测）。

## 3. 可空性原则（最小必填集）

**原则：除极少数字段外，一切字段可选——"缺失即未分析"，绝不因字段不全而拒绝写入。**
描述是渐进补全的：图片没有文本统计、文本没有调色板、LLM 还没跑过就没有 `llm-*`，
任何子集都必须能落库成功。

1. **唯一业务必填**：`file_path`（唯一键）。没有路径就没有这条元数据，其余一切皆可缺。
2. 现有 NOT NULL 列全部带默认值（`uuid`/`scope`/`attributes`/`download_count`/`is_deleted`/`created_at`/`updated_at`），
   默认值兜底，部分字段写入永远成功——现状合规，**保持不变**。
3. attributes 内字段天然可选：插件没跑就没有那个键；前缀闸门**只验前缀，不验完整性**。
4. `llm-` 轨同理：Annotation 允许任意子集提交（只传一个 `llm-tone` 也合法）。
5. **禁令**：今后新表、新列不得引入无默认值的 NOT NULL；唯一例外是充当键的必需字段（如 `file_path`）。

## 4. 硬编码插件字段（`cod-`）

### 4.0 插件触发关系

```
cod-basic ── 全量必跑（512B 头 + stat）
   ├─ textish=true → cod-text（≤5MB 全读）
   │    └─ 源码扩展名 → 追加 cod-code
   └─ image/* → cod-image（解码 + 降采样 128×128 分析）
```

每插件自带时间戳 `cod-<插件>-at`（unix 秒），重算时整族替换、只刷自己。

### 4.1 `cod-basic`（一切文件）

| 字段 | 类型 | 含义 | 示例 |
|---|---|---|---|
| `cod-basic-mime` | string | 魔数嗅探 MIME（读 512B 头） | `"image/png"` |
| `cod-basic-mime-match` | bool | 嗅探 MIME 与扩展名推断是否一致；false = 扩展名伪造嫌疑 | `true` |
| `cod-basic-mtime` | number | 文件系统修改时间（unix 秒）——注意与顶层 `updated_at`（元数据行时间）不同 | `1788271523` |
| `cod-basic-textish` | bool | 无 NUL 字节且控制字符占比低（GBK 等非 UTF-8 文本也算文本），text 插件闸门 | `true` |
| `cod-basic-entropy` | number | 香农熵 0-8 bits/byte：高≈加密/压缩，低≈文本 | `5.9` |
| `cod-basic-name-pattern` | enum | 文件名模式（纯正则）：`camera` / `screenshot` / `timestamped` / `hashlike` / `versioned` / `plain` | `"screenshot"` |

### 4.2 `cod-image`（png / jpg / gif / webp / bmp）

| 字段 | 类型 | 含义 | 示例 |
|---|---|---|---|
| `cod-image-width` / `cod-image-height` | int | 长宽（像素） | `1254` |
| `cod-image-aspect` | string | 约分比例 | `"1:1"` |
| `cod-image-orientation` | enum | `portrait` / `landscape` / `square` | `"square"` |
| `cod-image-megapixels` | number | 百万像素（1 位小数），"高清图"过滤用 | `1.6` |
| `cod-image-palette` | array | 前 5 主色（降采样后 k-means），上限 5 项 | `[{"hex":"#D4A373","ratio":0.34},…]` |
| `cod-image-dominant` | string | 第一主色 hex，单值便于精确过滤 | `"#D4A373"` |
| `cod-image-family` | enum | 色系（HSL 聚类）：`red`/`orange`/`yellow`/`green`/`cyan`/`blue`/`purple`/`warm`/`cool`/`neutral`/`grayscale`——即"主色调"。代码只产出 8 色相桶 + grayscale/neutral；warm/cool 保留给 llm 轨与人工标注 | `"orange"` |
| `cod-image-brightness` | number | 平均亮度 0-100 | `62` |
| `cod-image-contrast` | number | 亮度标准差 | `18.4` |
| `cod-image-grayscale` | bool | 是否黑白图 | `false` |
| `cod-image-has-alpha` | bool | 是否带透明通道 | `true` |
| `cod-image-animated` | bool | 是否动图 | `false` |
| `cod-image-frames` | int | 帧数（仅动图） | `24` |
| `cod-image-taken-at` | number | EXIF 拍摄时间（unix 秒），时间线检索刚需 | `1751460000` |
| `cod-image-camera` | string | EXIF 相机型号 | `"Pixel 9"` |
| `cod-image-software` | string | EXIF 软件字段 | `"ComfyUI"` |

**自由区**：

- `sp-cod-exif-*` —— EXIF 长尾（lens、gps、iso、光圈……成百上千种标签不枚举），键名 = EXIF 标签名小写下划线，如 `sp-cod-exif-lens`、`sp-cod-exif-gps-altitude`
- `sp-cod-png-*` —— PNG tEXt chunk 长尾。AI 生图工具（ComfyUI/NovelAI）把生成参数与 prompt 嵌在这里，键名 = chunk keyword，如 `sp-cod-png-prompt`、`sp-cod-png-parameters`

### 4.3 `cod-text`（textish 才跑，≤5MB）

| 字段 | 类型 | 含义 | 示例 |
|---|---|---|---|
| `cod-text-lines` | int | 行数（"文件长度"口径一） | `420` |
| `cod-text-chars` | int | 字符数（"文件长度"口径二） | `18200` |
| `cod-text-cjk-ratio` | number | 中日韩字符占比 0-1 | `0.87` |
| `cod-text-language` | enum | `zh` / `en` / `ja` / `mixed` / `unknown`（字符集启发式） | `"zh"` |
| `cod-text-encoding` | enum | `utf-8` / `gbk` / `latin-1` | `"utf-8"` |
| `cod-text-top-keywords` | array | 前 10 高频词（CJK 用 2-gram 频率统计、停用词过滤、无语义），上限 10 项 | `["梅贝尔", "触手", …]` |
| `cod-text-title-line` | string | 首个标题行或首行，截 80 字符——标题猜测 | `"# 第二章 深夜来电"` |
| `cod-text-headings` | array | 前 8 个标题——章节名/文档目录，上限 8 项 | `["第一章", "第二章", …]` |
| `cod-text-structure` | array | 检测到的结构（多选）：`headings` / `lists` / `code-blocks` / `tables` / `frontmatter` | `["headings","lists"]` |
| `cod-text-blank-ratio` | number | 空行率 0-1——日志与散文区分度很高 | `0.31` |

### 4.4 `cod-code`（源码扩展名追加）

| 字段 | 类型 | 含义 | 示例 |
|---|---|---|---|
| `cod-code-lang` | enum | 语言（按扩展名） | `"go"` |
| `cod-code-imports` | array | 前 10 条 import/require，上限 10 项 | `["fmt","pgx/v5",…]` |
| `cod-code-todo-count` | int | TODO/FIXME 计数，欠债可视化 | `3` |

### 4.5 二期占位（需要引库，暂不实现）

- `cod-audio-*`：duration / bitrate；自由区 `sp-cod-id3-*`
- `cod-video-*`：duration / resolution / codec
- `cod-arch-*`：zip 条目数 / 是否加密
- `cod-pdf-*`：pages

## 5. 模型字段（`llm-`）

### 5.1 固定字段（受控词表，解析器强制，共 7 个）

| 字段 | 类型 | 含义 | 示例 |
|---|---|---|---|
| `llm-semantic-type` | enum | **模糊类型**，词表：`novel` / `game_guide` / `technical_doc` / `note` / `log` / `meme` / `illustration` / `photo` / `screenshot` / `code_artifact` / `data` / `other` | `"game_guide"` |
| `llm-tone` | string | 基调：图像=色调氛围，文本=行文风格，短语 | `"暖橙温馨"` |
| `llm-characters` | array | 出现的人物/角色名，上限 10 项 | `["梅贝尔","铃仙"]` |
| `llm-action` | string | 图中在发生什么 / 文本主题动作，一句话 | `"少女在整理书架"` |
| `llm-style` | string | 艺术风格（二次元/写实/像素…）或文体 | `"日系动漫插画风"` |
| `llm-summary` | string | 一句话总结，≤100 字 | `"一张暖色调的书房插画"` |
| `llm-source` | string | 谁写的：`agent` / `ollama:<model>` | `"agent"` |

另有时间戳 `llm-at`（unix 秒）。`title` / `description` / `tags` 走顶层列，不在此区。

### 5.2 自由区

`sp-llm-*` —— 模型对单个文件的独特观察，任意增删，键名自由（建议小写中划线）：
`sp-llm-游戏名`、`sp-llm-章节进度`、`sp-llm-情绪值`……

## 6. 家族刷新语义

| 家族 | 重算行为 | 合并策略 |
|---|---|---|
| `cod-<插件>-*` | 整族替换（先删本插件旧键再写新键），算法升级即刷新 | 互不干扰 |
| `llm-*` | 不自动重算；新值 COALESCE 覆盖（非空才覆盖） | 保留旧值 |
| `sp-*` | 任意增删，永不整族清除 | 键级操作 |

## 8. 检索示例

```sql
-- 暖色系插画
attributes @> '{"llm-semantic-type":"illustration","cod-image-family":"warm"}'
-- 某角色出场的文件
```

## 9. 实现布局（`describer-go` 模块）

描述工具与 `mcp-server-go` 同级，独立 Go 模块，纯库形态（**字节进、事实出**，不依赖数据库）：

```
Mabel-s-Tentacles/
├── mcp-server-go/        # MCP + HTTP API（调用 describer-go）
├── describer-go/         # ← 本文档的实现载体
│   ├── go.mod            # module github.com/Reisentyann/Mabel-s-Tentacles/describer-go
│   ├── describer.go      # Descriptor 接口 + Facts + 注册表
│   ├── gate.go           # 前缀闸门（cod-/llm- 校验，纯函数）
│   ├── merge.go          # attributes 家族合并（整族替换/COALESCE，纯 JSON 操作）
│   └── plugins/
│       ├── basic/        # cod-basic
│       ├── image/        # cod-image（k-means、EXIF、PNG chunk）
│       ├── text/         # cod-text
│       └── code/         # cod-code
└── docs/元数据字段说明.md  # 本文档
```

接线方式（实现时的注意点）：

1. `mcp-server-go/go.mod` 通过 `replace github.com/Reisentyann/Mabel-s-Tentacles/describer-go => ../describer-go` 引用；
2. Docker 构建上下文必须改为**仓库根**（`docker-compose.yml` 的 `build.context: .`，`dockerfile: mcp-server-go/Dockerfile`），否则镜像里拿不到同级模块；
3. LLM 侧的 provider（Ollama 客户端等）将来也放本模块，同样保持无 DB 依赖。
