# 检索契约（agent 查询文件库的使用说明）

> **这是查询接口的正式契约，单一文件。** 模型在第一次查询之前先完整读这份文件；
> 读完即可独立完成「发现 → 圈人 → 取件」全流程，不需要任何其他前置知识。
> MCP-only 的 agent 无需读本文件：调一次 `list_index_fields`，目录项的
> `desc`/`bench` + 响应里的 `guide` 字段就是本契约第 4-6 节的机器副本。

## 1. 接口面（你能调什么）

| 入口 | 形态 | 用途 |
|---|---|---|
| `list_index_fields` | MCP 工具，参数 `prefix`（可选前缀过滤） | **发现**：全部可查字段 + 桶型 + 当前取值/值域 + 每字段 `desc`（含义）+ `bench`（分档）+ `guide`（规则与速查）。一次调用，会话内缓存 |
| `search_files` | MCP 工具，参数 `conditions`（条件：数组 = 全部 And，或 `{and/or/not}` 组合树，必填）+ `file_type`/`creator`/`scope`（复判过滤，可选）+ `page`/`size`（分页，默认 1/20，size 上限 100） | **圈人**：条件 → 命中文件简表（path/title/description/tags/size/updated_at） |
| `GET /api/index/fields?prefix=` | HTTP（JWT） | 目录的 HTTP 面（与工具同源同构） |
| `GET /api/files/search?cond=<URL编码>` | HTTP（JWT） | 条件检索的 HTTP 面（解析与工具同一份代码） |
| `read_file` | MCP 工具，参数 `path` | **取件**：读命中文件内容（1MB 截断防上下文撑爆） |

标准节奏：**`list_index_fields`（拿过就跳过）→ `search_files` → `read_file`**，两次查询类调用封顶。

## 2. 查询语义（conditions 怎么写）

### 2.1 叶子条件（单字段）

```json
{"field":"cod-text-language","op":"eq","value":"zh"}
```

- **结构**：`{field, op, value}` 三键齐全，缺一报 400/`success=false` 人话错误。
- **op 全集（8 个）**：

| op | value 形态 | 语义 | 适用桶型 |
|---|---|---|---|
| `eq` | 标量 | 相等 | enum / num / multi（multi=数组含该元素） |
| `in` | 数组 | 值 ∈ 集合（任一命中） | enum / num / multi |
| `gt` / `lt` | 数字 | 严格大于 / 小于 | num |
| `range` | `[lo, hi]` 双元数组 | 闭区间 | num |
| `ne` | 标量 | 不等于（只圈「有该键且值不同」的行；无键 ≠ 不等于） | 任意 |
| `exists` | `true` / `false` | 键存在性（`false` = 找没有该字段的文件） | 任意 |
| `contains` | 字符串 | 子串（字符串字段；数组字段任一元素含即中） | 任意 |

### 2.2 布尔组合（数组 = 与；对象 = and/or/not 树）

- **扁平数组 = 全部 And**（最常用，向后兼容旧写法）：

  ```json
  [{"field":"cod-text-language","op":"eq","value":"zh"},
   {"field":"cod-text-lines","op":"gt","value":50}]
  ```

- **要「或 / 非 / 分组」用组合对象，可任意嵌套**：

  ```json
  {"and":[
     {"or":[{"field":"cod-text-cjk-ratio","op":"gt","value":0.5},
            {"field":"cod-text-language","op":"eq","value":"en"}]},
     {"field":"cod-text-lines","op":"gt","value":200},
     {"not":{"field":"cod-text-timestamp-line-ratio","op":"gt","value":0.5}}
  ]}
  ```

  上面表达「(中文正文 或 纯英文) 且 长文 且 非日志」。
  规则：`and` / `or` 收数组（至少 1 项）；`not` 收单个节点（叶子、另一个组合、或数组=与皆可）；组合键**只能有一个**，不能与 `field/op/value` 混在同一对象里。

### 2.3 通用行为

- **空集是合法答案**：查一个不存在的取值返回 `success=true, total=0`——不是错误，不要重试。
- **坏条件立即人话报错**：未知 op、缺键、range 不是二元组、组合键混用等都返回 `success=false` + 原因（HTTP 400），照着错误信息改即可。
- **降级语义**：纯 And 的 `eq/in` 在索引异常时自动折回 SQL 兜底；**含 `or`/`not`，以及 `gt/lt/range/ne/exists/contains`，是索引专长**——索引不可用时直接报错而不是给错答案（宁缺毋滥）。
- 响应结构：`{success, page, size, total, files:[{path,title,description,tags,file_type,size_bytes,updated_at}]}`，按 `updated_at` 倒序（`order_by` 可改按属性值排序）。

## 3. 工作流与时序（什么时候查得到）

1. **写后不立即可查**：`write_file` 回执 = 盘写成功；描述落库 + 索引喂食走异步事件（秒级）。查不到刚写的文件 → 等一两秒重试，不是条件写错。
2. **发现结果可以缓存**：字段目录随库内文件动态增减（新文件带新字段即自动出现），但会话内基本稳定；只有「按理该命中却 total=0」时才刷新目录。
3. **服务重启不影响正确性**：索引是派生缓存，启动时从 DB 全量重建——查询口径不变。
4. **软删文件查不到**：软删行不挂索引，目录与查询都不含。
5. **复判过滤**：非 admin 会话只能命中自己读得到的文件（public / 自己的 / 本组的）——索引先圈人，复判再收口。admin 全见。

## 4. 通用口径规则（8 条，读值的正确姿势）

1. **op 与桶型适配**：enum 可 eq/in；num 可 eq/in/gt/lt/range；multi（数组字段）eq/in 任一元素命中即中（**并集语义，不是全含**）。
2. **比率类字段值域 0-1**，不是百分数：`gt 0.5` = 超过一半。
3. **纯计数字段 0 也产键**：`eq 0` 是常用的「找没有 X 的文件」（如 `checkboxes eq 0` = 干净文件）。
4. **比率分母为 0 不产键**（如无拉丁字母的文件没有 upper-ratio）：查不到 ≠ 值为 0。
5. **优先级：库内实测 > 先验分档**。目录的 `min`/`max`（num）与 `values`（enum）是当前库实况；本基准分档是跨库先验——本库 `lines max=21` 时，`gt 15` 就已是本库长文。
6. **分档是经验锚点不是真理**：边界附近放宽一档再复筛。
7. **`llm-*` 字段只有经过 LLM 描述的文件才有**——目录里它出现与否即覆盖率信号。
8. **`sp-cod-jm-*` 是 JMComic 稳定来源字段，已进入基准表**；其他 `sp-*` 自由区长尾不进基准表，靠目录 `values` 发现（如 `sp-cod-exif-lens`、`sp-llm-章节进度`）。

### 5.1 cod-basic（一切文件）
