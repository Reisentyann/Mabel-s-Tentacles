# MCP 聊天机器人趣味化功能设计

## 1. 现有项目能力分析

### 1.1 服务定位

当前项目是一个基于 Python 与 FastMCP 的 MCP 服务器，主要作为聊天机器人或上层 Agent 的工具执行后端。它通过标准 MCP Tool 接口，把系统命令执行、命令结果查询、文件写入与文件修改等能力暴露给模型调用。

服务器入口位于 `src/server.py`，运行方式为 SSE：

- 服务名：`agent-mcp-server`
- 默认端口：`8001`
- 启动方式：`mcp.run("sse")`
- 生命周期：启动时连接 PostgreSQL，关闭时断开数据库连接

### 1.2 已暴露 MCP 工具

| 工具名             | 参数                           | 当前能力                                        | 适合的聊天场景                           |
| ------------------ | ------------------------------ | ----------------------------------------------- | ---------------------------------------- |
| `execute_command`  | `command`, `user_id`           | 执行 Shell 命令，并把命令、状态、结果写入数据库 | 帮用户运行脚本、查看环境、执行自动化任务 |
| `get_results`      | `user_id`, `limit`             | 查询某个用户最近的命令执行历史                  | 回顾任务记录、解释上次运行结果           |
| `write_file`       | `file_path`, `content`         | 在 `data` 目录内安全创建或覆盖文件              | 写文章、生成代码、保存聊天产物           |
| `list_data_files`  | 无                             | 列出 `data` 目录下所有文件                      | 查看机器人保存的素材、设定、日志         |
| `modify_data_file` | `file_path`, `content`, `mode` | 追加或覆盖 `data` 目录内已有文件                | 更新笔记、追加故事、维护长期记忆         |

### 1.3 已有安全边界

项目已经具备一些基础安全设计：

- 文件写入与修改被限制在 `data` 目录内，防止目录穿越。
- 文件内容限制为 5MB，避免异常大文件占用资源。
- 文件路径禁止 Windows 盘符，降低越权写入风险。
- 命令执行器默认 60 秒超时，避免部分长时间任务卡死。
- 命令执行结果会记录到 PostgreSQL 的 `commands` 表中，便于查询与审计。

### 1.4 当前体验短板

从“让聊天机器人更有趣”的目标来看，当前 MCP 服务器更像通用工具箱，能力偏执行型，缺少以下面向互动体验的设计：

1. **缺少人格与情绪表达**：工具只返回结构化结果，没有角色语气、情绪状态或互动反馈。
2. **缺少长期趣味记忆**：虽然能写文件，但没有专门的记忆、设定、梗、偏好管理工具。
3. **缺少小游戏与互动玩法**：没有抽卡、占卜、骰子、问答、冒险故事等轻量娱乐能力。
4. **缺少结果再包装**：命令或文件操作结果比较朴素，不能自动变成更有趣的播报、吐槽或总结。
5. **缺少用户画像**：`user_id` 只用于命令记录，没有形成“每个用户不同体验”的个性化层。

## 2. 设计目标

本设计希望在不破坏现有 MCP 工具边界的前提下，让聊天机器人从“会执行任务的工具人”升级为“有记忆、有性格、会玩梗、能陪伴的互动伙伴”。

### 2.1 核心目标

- **更有趣**：增加随机事件、小游戏、吐槽、角色扮演、每日内容等互动能力。
- **更个性化**：基于 `user_id` 保存用户偏好、称呼、互动历史和专属设定。
- **更可持续**：把长期设定、故事进度、用户档案保存到数据库或 `data` 目录。
- **更安全**：趣味能力优先使用纯文本、随机数和受控文件读写，避免扩大 Shell 执行风险。
- **更易落地**：优先复用当前 FastMCP 工具模式、`src/tools/` 结构与数据库服务。

### 2.2 设计约束

- 不直接移除或改变现有工具接口，保持兼容。
- 新增工具应优先是确定边界的业务工具，而不是让模型直接拼接更多 Shell 命令。
- 涉及用户长期状态时，应以 `user_id` 隔离数据。
- 所有文件型记忆仍然必须限制在 `data` 目录内。
- 随机类玩法需要返回可解释的结果，避免黑盒输出。

## 3. 推荐新增功能

## 3.1 机器人人格系统

### 功能说明

新增机器人人格配置，让机器人可以在不同语气、身份和互动风格之间切换。例如：

- 元气助手：积极、夸张、喜欢鼓励用户。
- 毒舌搭子：轻微吐槽，但不攻击用户。
- 中二魔法师：把系统任务包装成魔法仪式。
- 赛博管家：冷静、专业、带一点机械幽默。
- 猫猫助手：句尾带可控程度的猫系表达。

### 建议工具

#### `set_bot_persona`

设置某个用户的机器人互动人格。

参数：

- `user_id: int`
- `persona: str`
- `intensity: int = 2`，范围 1-5，控制表现强度

返回：

- 当前人格名称
- 人格描述
- 示例回复

#### `get_bot_persona`

查询当前用户正在使用的人格。

参数：

- `user_id: int`

返回：

- 人格名称
- 强度
- 最近更新时间

### 落地方式

可以新增数据库表 `user_personas`：

| 字段         | 类型      | 说明     |
| ------------ | --------- | -------- |
| `user_id`    | int       | 用户 ID  |
| `persona`    | text      | 人格名称 |
| `intensity`  | int       | 表现强度 |
| `updated_at` | timestamp | 更新时间 |

如果暂时不改数据库，也可以保存在 `data/personas/{user_id}.json`。

## 3.2 长期记忆与用户档案

### 功能说明

让机器人记住用户偏好，例如称呼、喜欢的风格、雷点、常用项目、正在进行的故事等。

示例：

- “以后叫我舰长。”
- “我喜欢你用吐槽一点的语气。”
- “记住这个项目是 Mabel 的触手。”
- “我们的跑团角色是一只会写 Python 的章鱼。”

### 建议工具

#### `remember_user_fact`

保存用户记忆。

参数：

- `user_id: int`
- `key: str`
- `value: str`
- `category: str = "preference"`

返回：

- 保存是否成功
- 记忆摘要

#### `recall_user_facts`

查询用户记忆。

参数：

- `user_id: int`
- `category: str | None = None`
- `limit: int = 20`

返回：

- 记忆列表

#### `forget_user_fact`

删除某条记忆。

参数：

- `user_id: int`
- `key: str`

返回：

- 删除是否成功

### 趣味价值

长期记忆能让机器人形成“熟人感”。例如用户每次回来，机器人可以说：

> 欢迎回来，舰长。上次我们还停在“触手项目文件管理器”的部分，要继续拆它吗？

## 3.3 每日运势与随机事件

### 功能说明

增加轻量随机内容，让机器人每天都有一点新鲜感。可以包括：

- 今日运势
- 今日开发 Buff
- 今日 Bug 怪物
- 今日幸运命令
- 今日摸鱼指数
- 今日推荐人格

### 建议工具

#### `daily_fortune`

生成用户当天固定的趣味运势。

参数：

- `user_id: int`
- `theme: str = "developer"`

返回：

- 今日总运势
- 幸运关键词
- 幸运颜色
- 今日建议
- 今日禁忌
- 趣味短句

### 设计重点

同一个用户同一天的结果应保持稳定。可以使用 `user_id + 日期 + theme` 作为随机种子，避免用户重复调用时结果不断变化。

### 示例输出

```json
{
  "success": true,
  "fortune": "小吉",
  "lucky_keyword": "重构",
  "buff": "今天你发现隐藏 bug 的概率 +20%",
  "avoid": "不要在没喝水的时候改数据库迁移",
  "message": "今日适合清理 TODO，不适合和缩进吵架。"
}
```

## 3.6 命令结果趣味播报

### 功能说明

当前 `execute_command` 和 `get_results` 返回的是较朴素的执行结果。可以新增一个结果包装工具，把命令输出转化为更适合聊天的反馈。

### 建议工具

#### `summarize_command_result`

把命令执行结果转成自然语言总结。

参数：

- `user_id: int`
- `command_id: int | None = None`
- `style: str = "funny"`

返回：

- 任务是否成功
- 关键输出摘要
- 错误解释
- 下一步建议
- 趣味播报

### 示例

普通返回：

> exit_code = 1, stderr = ModuleNotFoundError

趣味播报：

> 任务失败了，但锅不大：Python 在现场找不到 `xxx` 模块。建议先检查依赖是否安装。错误怪物等级：Lv.2，推荐武器：`pip install`。

## 3.9 宝可梦式伙伴养成与对战

### 功能说明

新增一个“宝可梦式伙伴系统”，让聊天机器人不只是回答问题，还能陪用户收集、养成、训练和对战虚拟伙伴。为了后续可扩展和规避强绑定 IP 风险，系统内部可以使用“伙伴”“灵兽”“代码兽”等通用命名；对外交互则可以呈现为用户熟悉的宝可梦式玩法。

核心玩法包括：

- 捕捉伙伴：通过每日探索、随机事件、完成任务获得新伙伴。
- 伙伴养成：提升等级、经验、亲密度、技能熟练度和性格倾向。
- 属性克制：设计火、水、草、电、幽灵、钢、数据、混沌等属性。
- 技能学习：伙伴升级、完成训练或使用道具后解锁技能。
- 回合对战：用户选择技能，机器人计算伤害、状态和胜负。
- 图鉴收集：记录已遇见、已捕捉、已进化的伙伴。
- 进化系统：达到等级、亲密度或特殊条件后触发进化。

### 建议工具

#### `pet_explore`

进行一次探索，有概率遇到伙伴、道具或随机事件。

参数：

- `user_id: int`

返回：

- 探索区域
- 遭遇类型
- 遇到的伙伴或道具
- 可执行行动，例如捕捉、离开、战斗

#### `pet_capture`

尝试捕捉探索中遇到的伙伴。

参数：

- `user_id: int`
- `pet_id: str`
- `ball_type: str = "normal"`

返回：

- 是否捕捉成功
- 捕捉概率
- 伙伴基础信息
- 趣味捕捉播报

#### `pet_profile`

查看某个伙伴的状态。

参数：

- `user_id: int`
- `pet_id: str`

返回：

- 名称
- 等级
- 属性
- 当前经验
- 亲密度
- 技能列表
- 进化条件

#### `pet_train`

训练伙伴，提升经验、亲密度或技能熟练度。

参数：

- `user_id: int`
- `pet_id: str`
- `training_type: str = "balanced"`

返回：

- 获得经验
- 属性成长
- 是否学会新技能
- 是否触发进化

#### `pet_battle_start`

开始一场对战。

参数：

- `user_id: int`
- `pet_id: str`
- `opponent_type: str = "wild"`

返回：

- 对战 ID
- 我方伙伴状态
- 敌方伙伴状态

#### `pet_battle_turn`

执行一回合对战。

参数：

- `user_id: int`

返回：

#### `pet_pokedex`

查看用户图鉴。

参数：

- `user_id: int`
- `filter: str | None = None`

返回：

- 已遇见数量
- 已捕捉数量
- 已进化数量
- 图鉴条目列表

### 战斗规则建议

第一版可以使用轻量回合制规则，避免复杂度过高：

```text
最终伤害 = 技能威力 + 攻击方等级修正 + 属性克制修正 - 防御方防御修正
```

属性克制建议先做简单倍率：

- 克制：`1.5x`
- 普通：`1.0x`
- 被抵抗：`0.5x`

伙伴状态可以先支持 4 种：

- `normal`：正常
- `burn`：每回合少量扣血
- `stun`：概率跳过行动
- `shield`：下次受到伤害降低

### 养成循环

推荐形成一个每日可玩的闭环：

1. 用户调用 `daily_fortune` 获得今日探索 Buff。
2. 用户调用 `pet_explore` 遇到野生伙伴或道具。
3. 用户调用 `pet_capture` 捕捉伙伴。
4. 用户调用 `pet_train` 提升等级和亲密度。
5. 用户调用 `pet_battle_start` 和 `pet_battle_turn` 进行对战。
6. 对战胜利后获得经验、道具、成就或图鉴进度。


### 趣味示例

用户：

> 主人我要去草丛里抓一只新的伙伴。

机器人调用：

```json
{
  "tool": "pet_explore",
  "arguments": {
    "user_id": 1,
    "area": "debug_forest"
  }
}
```

## 4. 优先级路线图

### P0：低风险、高趣味、最快落地

3. `set_bot_persona` / `get_bot_persona`：可先用 JSON 文件保存用户人格。

### P1：增强个性化与留存

3. `summarize_command_result`。
4. 基于使用次数自动触发成就。
5. `pet_explore` / `pet_capture` / `pet_profile`，先完成伙伴收集与基础养成。

## 6. 数据存储建议

### 6.1 文件存储方案

适合早期快速实现：

```text
data/
  personas/
    1.json

    1.json
  pets/
```

优点：

- 实现简单。
- 方便前端文件视图展示。
- 复用当前文件安全策略。

缺点：

- 并发写入需要额外锁。
- 查询能力弱。
- 后期迁移到数据库需要转换脚本。

### 6.2 数据库存储方案

适合长期稳定运行：

```sql
CREATE TABLE user_personas (
    user_id INT PRIMARY KEY,
    persona TEXT NOT NULL,
    intensity INT NOT NULL DEFAULT 2,
    updated_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE user_memories (
    id SERIAL PRIMARY KEY,
    user_id INT NOT NULL,
    category TEXT NOT NULL,
    key TEXT NOT NULL,
    value TEXT NOT NULL,
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW(),
    UNIQUE(user_id, key)
);

CREATE TABLE user_achievements (
    id SERIAL PRIMARY KEY,
    user_id INT NOT NULL,
    achievement_key TEXT NOT NULL,
    unlocked_at TIMESTAMP DEFAULT NOW(),
    UNIQUE(user_id, achievement_key)
);
```

## 7. 安全与风控建议

趣味功能不应降低当前 MCP 服务安全性。建议遵守以下原则：

1. **随机和文本类工具优先**：新增趣味能力尽量不依赖 Shell。
2. **人格强度可控**：避免毒舌人格输出攻击性、歧视性或冒犯性内容。
3. **用户记忆可删除**：必须提供遗忘能力，用户可以删除不想保存的信息。
4. **故事内容可重置**：长期互动状态应支持清空或重开。
5. **文件路径继续受限**：所有新文件能力仍必须写入 `data` 目录。
6. **命令总结不重复执行命令**：`summarize_command_result` 只读取历史结果，不应再次执行 Shell。
7. **限制卡片与记忆大小**：单条记忆、故事状态和卡片应设置大小上限。
8. **对战计算在后端完成**：伙伴属性、伤害、捕捉概率和奖励应由工具端计算，避免由模型随意改数值。
9. **限制每日收益**：探索、训练和对战奖励应设置每日上限，防止刷资源破坏养成平衡。

## 9. 总结

当前 MCP 服务器已经具备命令执行、结果查询和安全文件操作等基础能力，适合作为聊天机器人的工具后端。要让机器人更有趣，建议优先增加“人格系统、每日随机内容、骰子抽签、长期记忆、成就系统、互动故事”这些偏文本与状态管理的工具。

如果希望进一步提升长期留存，建议加入宝可梦式伙伴养成与对战系统。它能把每日运势、随机探索、成就、记忆、文件卡片和人格播报串成一个持续循环，让用户每天都有理由回来看看自己的伙伴成长。

最推荐的第一阶段方案是：

1. 增加 `daily_fortune`，提供每日固定趣味内容。
2. 增加 `roll_dice` 和 `random_choice`，提升即时互动性。
3. 增加 `set_bot_persona` 和 `get_bot_persona`，让机器人拥有可切换人格。
4. 使用 `data` 目录保存人格与轻量状态，避免一开始引入复杂数据库迁移。
5. 第二阶段增加 `pet_explore`、`pet_capture` 和 `pet_train`，形成收集与养成闭环。

这样可以在最小改动下显著提升聊天机器人的趣味性，并为后续长期记忆、跑团故事和成就系统打下基础。
